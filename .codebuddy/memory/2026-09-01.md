# 2026-09-01 工作日志

## 骨架屏淡入：探针 ImageOpened 后延迟一渲染帧（继续优化 B 方案）

### 背景
上一轮（2026-08-31）已确认闪烁根因：`ImageBrush` 无「可绘制」信号，改用透明探针 `Image` 的
`ImageOpened` 作门闩，闪烁大幅改善。但用户反馈「没有渐变的效果 + 偶发闪一下」。

### 分析（本轮根因）
探针 `ImageOpened` 只保证**探针 Image 自身**可绘制。探针与 ImageBrush 虽共享同一 BitmapImage
（纹理只解码一次），但 **ImageBrush 的纹理上传到 GPU 可能比探针晚一渲染帧**。立即播放动画时，
动画前段淡入的是空白（ImageBrush 无纹理），纹理就绪瞬间图片突现 —— 观感即「无渐变 + 偶发闪」。

### 实施（仅 ThumbnailPresenter.cs）
- 新增 `PlayFadeInNextFrame()`：`CompositionTarget.Rendering` **单次订阅**，下一渲染帧回调后立即解除。
  回调内校验 `State==Loaded && _imageOpened` 才 `ShowImageWithFadeIn()`（等待期间可能滚走/失败）。
- 两条淡入路径统一走 `PlayFadeInNextFrame()`：
  ① `OnImageOpened` 消费 `_pendingFadeIn` 时；② `ApplyVisualState` 中 `isSkeletonToImage && _imageOpened` 直接路径。
- 新增 `CancelPendingFrame()`：`DataContextChanged`/`Unloaded` 时解除未触发的 `Rendering` 订阅，
  防止容器复用后残留回调误触发。
- 字段 `_pendingRenderFrame` 防重复订阅。

### 验证（每项单独列出）
- `dotnet build src/Pixbian/Pixbian.csproj -warnaserror`：**通过**（0 Warning 0 Error）
- `dotnet test Pixbian.sln`：**通过**（160 个：Core 115 / WebServer 33 / Imaging 12）
- `read_lints`（src/Pixbian）：**通过**（0 诊断）
- 用户实测（待反馈）：应看到骨架 → 图片 250ms 渐变，无突现感

### 教训
- **Image 控件的 ImageOpened 与其享 BitmapImage 的 ImageBrush 渲染不同步**：前者只保证自身
  可绘制，后者纹理上传可能晚一帧。共享资源的两条渲染路径就绪时机需分别考虑。
- 等「下一渲染帧」用 `CompositionTarget.Rendering` 单次订阅（回调即退订），比固定延迟更精确、
  无魔法数；但必须配套 `CancelPendingFrame` 处理容器复用/卸载。

## 完整排查链

### 主排查：8 轮（2026-08-31 完成，根因在第 8 轮）

| 轮次 | 用户反馈 | 根因 | 修复 |
|---|---|---|---|
| 1 | 从骨架到图片有抖动 | 骨架填满容器 vs 图片 Uniform 渲染区，形状不匹配 | 骨架按 Uniform 算法定尺寸 |
| 2 | 一闪一闪 | 升级加载把已显示图片打回骨架 | `Thumbnail is null` 才置 Loading |
| 3 | 完成显示后还闪 | 跃迁判据过宽（容器复用串味） | 判据改为「上一次是 Loading」+ DataContextChanged 清理 |
| 4 | 还闪 | 自适应视图首帧按正方形请求 → 升级必现 | 按宽高比估算首帧尺寸 |
| 5 | 还闪 | 淡入先于 Source 设置（空淡入） | 挂起等 Source |
| 6 | 还闪 | `GoToState(Loaded)` 抢在 Source 前 → 双透明空白帧 | Source 未就绪时保持骨架，同帧切换+淡入 |
| 7 | 还闪 | 位图解码异步，淡入的是未解码位图 | 等 `PixelWidth>0` / 位图级 ImageOpened |
| **8** | **还闪（最终根因）** | **信号源级别错：位图级 ≠ 控件级「可绘制」** | 透明探针 Image 的 `ImageOpened` 作门闩 |

**第 8 轮的关键洞察**：`BitmapImage.PixelWidth>0` 只表示 CPU 解码完成；纹理上传 GPU 在其后异步进行，
且服务层返回的位图早已解码、位图级 `ImageOpened` 已错过。`ImageBrush` 本身无「可绘制」信号。
唯一可靠信号是 **`Image` 控件的 `ImageOpened`**（控件级，无论是否缓存都触发）。
因 WinUI 3 的 Image 无 CornerRadius，最终采用 **ImageBrush 显示 + 透明探针 Image 拿信号** 的双层结构。

# 图库页工具栏：全选菜单图标 + 快捷键 + 按钮悬停底色

## 需求与实现
1. 「更多」菜单两项加图标并应用快捷键：全选 `E8B3` Ctrl+A、不选择任何项目 `E711` Esc + Ctrl+D
2. 工具栏按钮 hover 需要可见的背景色

## 关键结论（可复用）
- **WinUI 3 的 Button 悬停用 Storyboard（`ObjectAnimationUsingKeyFrames`）而非 `VisualState.Setters`**，
  动画优先级最高，本地值 `Background="Transparent"` **挡不住它**。所以「设了本地值导致 hover 失效」是错的判断方向。
  本项目 hover 看不见的真因是：默认 `ButtonBackgroundPointerOver`（ControlFill 次填充）铺在纯白内容区上太淡。
- 修法沿用项目既有模式：在 Page.Resources 用 `<StaticResource x:Key="ButtonBackgroundPointerOver" ResourceKey="SubtleFillColorSecondaryBrush"/>` 覆盖主题键（约 6% / 9% 覆盖），Pressed 对应 `SubtleFillColorTertiaryBrush`。
  App.xaml 的 NavigationView 项已用同一对键，观感与系统一致。
- **主题键覆盖不要放进 `Style.Resources`**：Style 的 Setter.Value 是单一实例，多个元素共享同一 ResourceDictionary
  会触发「已是其他元素的子项」异常。覆盖放在 Page.Resources（页面内只有工具栏用 Button，无副作用）。
- **快捷键用页面级 `Page.KeyboardAccelerators`**，`KeyboardAcceleratorTextOverride` 只负责菜单上的提示文本。
  Accelerator 沿焦点树向上查找：焦点在页面内才生效；焦点停在左侧 NavigationView（页面外的兄弟节点）时不响应，
  这是平台行为，不是 bug。菜单展开时 Esc 会被 MenuFlyout 先消费（关闭菜单），属预期。
- 全选快捷键需先切到选择模式：非选择模式下条目无复选框与遮罩，直接全选没有任何视觉反馈。

## 文件清单（2 个）
- `src/Pixbian/Views/GalleryPage.xaml`：Page.KeyboardAccelerators（3 条）、两处「更多」菜单图标+快捷键文本、Page.Resources 覆盖两个按钮状态键、头部注释
- `src/Pixbian/Views/GalleryPage.xaml.cs`：新增 `OnSelectAllAcceleratorInvoked` / `OnSelectNoneAcceleratorInvoked`

## 追加：hover 背景加圆角
- 在 `ToolBarButtonStyle` 显式设 `CornerRadius=6`。默认样式的 `ControlCornerRadius` 是 **4**，
  在 32px 高的纯图标按钮上圆角几乎看不出来。Button 默认模板的 ContentPresenter 有
  `CornerRadius="{TemplateBinding CornerRadius}"`，所以设属性即可，无需重写模板。
- **不能用 `BasedOn="{StaticResource DefaultButtonStyle}"` 兜底**：XAML 要求 BasedOn 的 TargetType
  必须是当前 TargetType 的**基类或同类型**；Button 是 ButtonBase 的派生，反向引用会抛异常。
- 不要全局覆盖 `ControlCornerRadius`（会影响 TextBox / ComboBox 等所有控件）。

# 图库页工具栏改造 + 排序模型重构

## 需求
1. 工具栏除「选择」外全部去掉文字标签，只留图标（靠 ToolTip 说明）
2. 排序菜单改为「依据（随机 / 日期 / 大小 / 名字）+ 方向（升序 / 降序）」两组，默认**修改日期降序**，随机时方向两项禁用
3. 筛选菜单：所有媒体 / 照片 / 视频，默认所有媒体
4. 显示模式：等高 / 方形 + 小 / 中 / 大，默认**等高-中**
5. 删除「刷新」按钮

## 关键设计决策
- **排序由一维枚举拆成两维**：原 `MediaSortOrder`（TakenDescending 等 4 个组合值）无法表达「依据 × 方向」，
  改为 `MediaSortKey`（Random / ModifiedDate / FileSize / FileName）+ `SortDirection`（Ascending / Descending），
  UI 两组 RadioMenuFlyoutItem 与领域模型一一对应，页面零映射代码。
- **随机排序不能用 SQL `RANDOM()`**：增量分页每次都是新的全表随机序，翻页会重复或漏条目。
  改为 `MediaQuery.RandomSeed` + `(id * @seed) % 1000003` —— 同种子下顺序稳定可分页，
  重新点「随机」才由 `GalleryViewModel` 换种子。
- **排序日期语义改为修改日期**（`modified_utc`），不再是 `taken_utc`。
- SQL 仍保持「参数化 CASE 切换排序表达式」的写法（排序键与方向都是参数），不拼接字段。
