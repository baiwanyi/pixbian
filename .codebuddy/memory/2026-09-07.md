## 主窗口背景：jpg 壁纸改为照片应用同款双层渐变（实测取色）

- **实测结论（照片应用背景真相）**：窗口底色近乎纯色的垂直微渐变——深色 #1D2125→#1F2022、浅色 #EFF4F9→#F1F3F8，「光晕感」实质是顶部冷蓝调；「内容区比左栏亮一档」由内容层底色承担，Pixbian 用半透明内容卡片叠加自动复现（合成值验算与照片内容区吻合），故卡片色未动。

## 设置按钮悬停「调色无变化」根因确诊 + 修复（用户反馈）
- **关键确诊**：用户把 Hover 改成纯黑 #000000 仍无变化 → Button.Resources 级的 `<ThemeResource>` 键重定向**根本不被默认模板 VisualState 解析**——此前看到的淡色一直是系统默认 5% 黑，历次调色值自然全部无效。
- **修复（借鉴 Short 页已验证模式）**：把 `ButtonBackgroundPointerOver/Pressed` 两键的 ThemeResource 重定向从 `Button.Resources` 挪到 **`TitleBar` Grid.Resources（模板外父级）**——Short 页在 Page.Resources（同为模板外父级）的同机制覆盖是实证有效的。Hover 12% / Pressed 20% 色值不变。
- **通用结论（沉淀）**：WinUI 3 默认模板 VisualState 的 ThemeResource 解析会跳过 templated parent 自身的 Button.Resources；覆盖模板状态键必须放在「模板外」的祖先级 Resources（Page/父 Grid/App 主题字典）。控件模板内状态调色无效时先查覆盖位置是否在模板内。
- 涉及文件：`src/Pixbian/Views/MainWindow.xaml`、`src/Pixbian/App.xaml`（注释更新，恢复用户误改的 #000000 → #1F000000）。构建 0 警告 0 错误。

## 设置按钮悬停终局：自定义 ControlTemplate（浅色仍非所设色）
- 现象：事件驱动下深色可见、浅色"有反馈但不是设定的 18% 黑"——默认模板状态下事件设置的画刷疑似被系统状态行为稀释/干扰，根因未能定位。
- **终局方案**：设置按钮改自定义 ControlTemplate——模板仅 `Border(TemplateBinding Background/CornerRadius) + ContentPresenter`，**不含任何 VisualState**，背景所见即所设，彻底排除默认模板状态的一切干扰；事件驱动保留（浅 18% 黑/深 12% 白）。代价：失去默认模板的按下微交互（此前本地 Background 也早已压死状态背景，观感无退化）。
- **通用结论**：Button 悬停色定制历经「资源键覆盖（Button/祖先两级）→ 事件驱动 → 自定义模板」三级演进；若事件驱动仍被干扰，自定义模板剔除全部状态是最终确定性手段。
