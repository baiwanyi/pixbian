## 修复等高视图错位（第二轮）

### 根因（实测诊断）
通过 JustifiedPanel 临时日志 + 视觉树转储证实：WinUI 分组 GridView 使用非分组感知的自定义 ItemsPanel 时，面板 children 是 23 个 `GroupItem` 组容器（被按 aspect=1.0 排成 256×256 格子），组内条目由内建竖排 StackPanel 渲染——JustifiedPanel 从未作用于媒体条目，每组内容被 256px 窗口裁切产生「残条」错位。**该视图此前从未真正实现过等高布局。**

### 修复（用户选择保留多选的方案）
等高视图改为显式组合结构：外层 ScrollViewer + ItemsControl 按组迭代（x:DataType=MediaGroupViewModel），每组 = 组头 TextBlock + 非分组 GridView（ItemsPanel=JustifiedPanel、禁用内层滚动、共享 MediaItemTemplate）。用户选择保留多选（否决了暂不支持多选的轻方案）。

- JustifiedPanel.cs：移除临时诊断日志与 DumpVisual；
- GalleryPage.xaml：JustifiedGridView 替换为 ScrollViewer+ItemsControl+组内 GridView 结构；
- GalleryPage.xaml.cs：`_justifiedGrids` 元组列表（Loaded 登记/Unloaded 注销）、CollectSelection 聚合各分组控件选择、SelectionModeToggle 联动循环、OnJustifiedGridLoaded 同步行高与选择模式、双击改为从 OriginalSource 沿视觉树向上找 GridViewItem（修复原 DataContext 方式在两种视图下均失效的问题）、移除 JustifiedRowHeight 属性（行高改由代码后置直接设置，因模板内无法 x:Bind/ElementName 跨 namescope）。

### 经验教训（WinUI 分组 + 自定义 ItemsPanel）

### 经验教训（WinUI 分组 + 自定义 ItemsPanel）
**WinUI/UWP 分组 ListViewBase（GridView/ListView）配自定义 ItemsPanel 时，面板排列的是 GroupItem 组容器而非条目容器，组内条目回落到内建面板**——自定义行式布局面板在分组场景必须用「每组一个非分组控件实例」的组合结构实现，不能像 ItemsWrapGrid/ItemsStackPanel 那样指望面板自动感知分组。此知识点对该项目后续布局改造具有普适性。

## GalleryPage 编译错误修复（恢复 .bak_test2 后）

### 背景

### 修复清单
1. **VisualStateGroups 语法**：`ControlTemplate.VisualStateGroups` / `Grid.VisualStateGroups` 均非法，WinUI 3 必须用 `<VisualStateManager.VisualStateGroups>` 作为 `ControlTemplate` 内 `Grid` 的子元素（闭合标签同步修正）。
2. **C# 键盘事件**：`Page` 的键盘事件在 WinUI 3 中名为 `ProcessKeyboardAccelerators`（复数）+ 参数类型 `ProcessKeyboardAcceleratorsEventArgs`；`VirtualKey` 需 `using Windows.System;`。改为与项目其他页一致的 `KeyDown` + `KeyRoutedEventArgs` 模式处理 F5。
3. **BoolToVisibilityConverter 命名空间**：该类型在 `PhotoApps.Converters`，XAML 资源中误用 `local:`（= PhotoApps.Views），新增 `xmlns:converters` 前缀并改用之。
4. **MediaGroupTemplateSelector 移出代码后置**：内部嵌套类在 MarkupCompile 阶段尚未编译，XAML 资源引用报错 WMC1110。迁移到独立文件 `Views/MediaGroupTemplateSelector.cs`（保持 internal sealed、DataTemplateSelector）。
5. **ItemsPanelTemplate 内 RowHeight**：用 `x:Bind ViewModel.ThumbnailSize` 在 ItemsPanelTemplate 中要求 x:DataType 且无法触达页面属性，改用传统 Binding `Binding ViewModel.ThumbnailSize`（页 DataContext=this 且模板不在 DataTemplate 内，可用）。
6. **CheckBox 可见性绑 IsSelectionMode**：ItemContainerStyle 的 ControlTemplate 中 x:Bind 根固定为 GridViewItem，无法触达页面属性；WinUI 3 x:Bind 不支持 RelativeSource / AncestorType。新增 `GridViewItemSelectionHelper` 附加属性 `IsInSelectionMode`，页面在 `IsSelectionMode` setter 遍历已生成容器设值、`OnContainerContentChanging` 对新生成容器补设；模板内 `Visibility` 用传统 `Binding Path=(local:GridViewItemSelectionHelper.IsInSelectionMode), RelativeSource=TemplatedParent`。
7. **Csproj 调试属性保留**：`BaseIntermediateOutputPath` 绝对化 + `XamlCompilerExePath` 指向 net472 exe 已验证让 `dotnet build`（Core 宿主）也能成功（此前失败因 interop.targets 损坏，现已恢复）。

## 修复启动即崩溃（0xc000027b / InvalidCastException「不支持此接口」）

### 现象
`run.ps1` 构建成功（0 警告 0 错误）、exe 存在，但进程启动后数秒静默退出，退出码 `-1073741189`（0xC000041D）。
Windows 事件日志：出错模块 `Microsoft.UI.Xaml.dll`，异常码 `0xc000027b`（XAML stowed exception）；
`%LOCALAPPDATA%\Pixbian\Logs\crash.log` 只记录到**无托管堆栈**的 `System.InvalidCastException: 不支持此接口`
（E_NOINTERFACE，0x80004002），且 `e.Handled = true` 也无法阻止进程终止。

### 二分定位过程（每轮：改一处 → 构建 → 启动观察 15 秒）
1. 组内 GridView 的 `JustifiedPanel` → `ItemsWrapGrid`：**仍崩**（排除自定义面板）。
2. 外层 `ItemsControl.ItemsPanel` 由 `ItemsStackPanel` → 普通 `StackPanel`：**仍崩**（排除虚拟化面板）。
3. 移除等高视图 `ScrollViewer` 的 `ViewChanged="OnScrollViewChanged"`：**仍崩**（排除触底增量加载）。
4. 移除组内 GridView 的自定义 `ItemContainerStyle`（ControlTemplate）：**不再崩溃** → 元凶锁定容器模板内的绑定。
5. 仅把 CheckBox 的 `Visibility` 改为 `Collapsed`（保留模板其余部分）：**不再崩溃** → 精确到该绑定。

### 根因
`Visibility="{Binding Path=(local:GridViewItemSelectionHelper.IsInSelectionMode), RelativeSource={RelativeSource Mode=TemplatedParent}}"`
——`(Namespace:Owner.Property)` 形式的**自定义附加属性路径是 WPF 语法，WinUI 3 的 {Binding} 不支持**；
XAML 解析目标属性失败返回 E_NOINTERFACE，被转成 stowed exception 直接终止进程。
把承载类型从 `internal` 改为 `public` 后**仍然崩溃**，证实与类型可见性无关，是属性路径语法本身不支持。

### 修复

  等高（GroupTemplate）与网格（GridViewControl）**两处** CheckBox 的 `Visibility`
  统一改为 `{Binding Data.IsSelectionMode, Source={StaticResource PageProxy}, Converter={StaticResource BoolToVisibility}}`。

### 经验教训（WinUI 3 模板内跨 namescope 取页面属性）
- `ControlTemplate` / `DataTemplate` 内 x:Bind 的根固定为模板化控件或条目，无法触达页面；
  WinUI 3 既不支持 `RelativeSource AncestorType`，也不支持 `(local:Type.Property)` 附加属性路径绑定。
- 可靠做法是**页面资源里的绑定代理对象**（`Data="{x:Bind}"` 绑页面自身）+ 模板内 `{Binding Data.X, Source={StaticResource PageProxy}}`；
  页面须实现 `INotifyPropertyChanged` 才能刷新。
- 此类错误在构建期完全静默，运行期表现为进程直接终止（0xc000027b），托管端只留一个无堆栈的
  `InvalidCastException`，定位必须靠「逐个移除 XAML 片段」的二分法。
