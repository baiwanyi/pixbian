## 补充：注册已成功（同日后续）

最终包：`Pixbian_1.0.0.0_neutral__h94vh5tyrgn60`

真正的四个关键点：
1. **必须用两级证书**：单张自签证书同时充当根与叶子时链构建不稳定（signtool 报 `0x80096019`、Add-AppxPackage 报 `0x800B0109`）。改为根 CA（`CN=Pixbian Root`）签发代码签名叶子（`CN=Pixbian`）后 `signtool verify` 立即通过。
2. **根证书必须导入 LocalMachine**：包由 AppX 部署服务（系统上下文）校验，只看得见本机存储。仅导入 CurrentUser 会报 `0x800B010A`（无法建立到信任根颁发机构的证书链）。导入 `LocalMachine\Root` 需管理员。
3. **PFX 含两张证书时签名必须指定 `/sha1 <叶子指纹>`**，否则 SignTool 报"找到多个证书"而不签名。
4. **`Add-Type -AssemblyName System.Security` 会破坏 `CertificateRequest` 的类型解析**（构造函数的密钥参数被解析成 null）。因此脚本不用它，也因此不设置 EKU（`OidCollection` 在该程序集内）；未限定 EKU 的证书等同全用途，代码签名成立。

## 实施：P1-3 键集分页（用户选方案 A，FTS5 部分经评估放弃）
- **关键发现（重要，勿再走弯路）**：FTS5 对中文子串搜索不可行——分词器按空白/标点切词，中文整句成单 token；`trigram` 分词器要求查询 **≥3 字符**，中文搜索词以 2 字居多，FTS5 无法加速且语义劣于 `LIKE '%词%'`。结论：放弃 FTS5 保留 LIKE；如未来需要可评估混合路径（≥3 字符走 trigram，其余回退 LIKE）。
- **键集分页实施**：`MediaQuery.Keyset` + `KeysetCursor(LastId, LastText, LastNumber, LastUtc)`（按排序键分字段避免装箱）；`QueryAsync` 非随机排序走「排序值 + id」双键比较（拼接仅内部列名常量，值全参数化；modified_utc 文本字典序=时间序，BINARY 比较与 ORDER BY 天然一致）；旧 OFFSET 路径保留兼容。`GalleryViewModel` 以 `_items[^1].Item` 构造游标，删除收缩后天然避免 OFFSET 错位。
- 踩坑：首版按「isText 二分」绑定游标，ModifiedDate 的值在 `LastUtc` 却被绑成 `LastText`（null）→ 第二页恒空。改为 `ResolveKeysetCursor` 按排序键三分支解析并复用 `FormatUtc`，游标格式与库内存储不漂移。
- **10 万条实测**（临时基准，已删）：插入 31.6 s；OFFSET 第 251 页 151 ms vs 键集 1 ms = **151×**，OFFSET 随页深线性恶化、键集恒定。
- 验证：build -warnaserror 0 警告 0 错误；测试 273 通过（Core 221 / Web 38 / Imaging 14）。
- 基准方法论：键集对比必须取**中部页**（末页之后无剩余条目，键集结果为空集无法对比）。
