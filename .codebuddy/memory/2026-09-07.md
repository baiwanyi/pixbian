## Short 页第六轮：空格误触修复 + 播放按钮外观（用户反馈）
- **空格误触根因（重要）**：点击覆盖层按钮后焦点留在按钮上，空格键变成「激活聚焦按钮」——焦点在收藏按钮上时空格执行的是收藏而非页面暂停（页面 KeyDown 收不到，被按钮吞）。修复：`OnOverlayButtonTapped` 拦截 Tapped 时顺带 `Focus(FocusState.Programmatic)` 归位；菜单项（OnViewOriginalClick/OnDeleteClick）点击后也归位——MenuFlyout 关闭会把焦点还给锚定按钮，不归位空格会再次触发它。**通用结论：页面级键盘快捷键与可聚焦控件并存时，任何点击路径都必须把焦点交还页面，否则空格/回车会被聚焦控件劫持。**

## Short 页第七轮：空格根治（全局加速器）+ 移除点击暂停（用户反馈）
- **空格失灵根治**：焦点归位补丁与 IsTabStop=False 均无效 → 换方案：页面级 `Page.KeyboardAccelerators`（Space/Left/Right/Delete，`Invoked=OnAcceleratorInvoked` 统一入口），**不设 ScopeOwner 即默认全局范围**——窗口内任意焦点位置都触发，彻底不依赖焦点落点；触发即 `args.Handled=true`，菜单项 DEL 不会双重执行；移除页面 KeyDown 订阅与 OnPageKeyDown（避免双路径）。
- **关键事实（XamlCompiler 实测）**：WASDK 2.3.6 的 `KeyboardAccelerator` **没有 Scope 属性**（WMC0011）——成员经包内 Microsoft.WinUI.xml 核实只有 Key/Modifiers/IsEnabled/ScopeOwner；`ScopeOwner=null` 即全局。**另外印证记忆条目「Page.KeyboardAccelerators 污染页面内所有 ToolTip」在本页无碍——页面 ToolTip 已全部移除。**
- 移除「点击画面播放/暂停」（StageRoot.Tapped + OnStageTapped）：与中央播放按钮冲突（用户反馈会造成无法继续播放）；播放/暂停唯一入口 = 空格 + 中央按钮。OnOverlayButtonTapped 的 Focus 归位一并移除（无意义），保留 e.Handled 防御性拦截。OnLoaded 的 Focus 也移除（不再依赖焦点）。
- 涉及文件：`src/Pixbian/Views/ShortPage.xaml`、`src/Pixbian/Views/ShortPage.xaml.cs`。构建 0 警告 0 错误。
- **二次修复（Tapped 归位不可靠）**：用户反馈空格仍失灵 → 根除方案 `ShortOverlayButtonStyle` 加 `IsTabStop=False`（Setter 级一处覆盖全部覆盖层按钮，含中央播放按钮）：按钮不参与键盘焦点、点击也不抢焦点，焦点永不离开页面，空格恒由页面 KeyDown 接管。教训：**页面级快捷键与按钮并存时，靠事件回调归位焦点是补丁不可靠，按钮级 IsTabStop=False 才是正解**（前提：本页无键盘 Tab 导航需求）。构建 0 警告。

## Short 页第九轮：进入页面空格失灵（用户反馈，第八轮删焦点逻辑的回归）
- 现象：点【片段】进入页面后空格/方向键全部失灵（点击下一个按钮也无效），**点击一次画面后才恢复**——用户实验定位了「焦点停留在导航项等窗口控件上时，全局 KeyboardAccelerator 也会被该控件的内部按键处理抢先而失效」。第八轮删掉 OnLoaded 聚焦与点击归位是回归根因：accelerator 的「全局」对「焦点在窗口控件上」的边界并不成立。
- 修复（不恢复点击暂停）：①`OnLoaded` 恢复 `Focus(FocusState.Programmatic)`；②新增 `StageRoot.PointerPressed → Focus` 纯焦点归位（不标记 Handled、不执行播放/暂停，与用户「移除点击暂停」诉求不冲突）；③OnOverlayButtonTapped 保持纯 Handled（按钮 IsTabStop=False 点击不抢焦点，焦点已在页面）。
- **通用结论（修正第八轮教训）**：全局 KeyboardAccelerator 不是焦点免疫——焦点被窗口其他控件持有时，其内部按键处理（如 NavigationViewItem 空格激活）会先于加速器吃掉按键；页面级快捷键仍须「进入页面聚焦 + 点击归位」双保障。

- 用户决策：空格键彻底放弃，恢复「点击画面任意位置播放/暂停」，并强调与中央播放按钮不冲突。
- 实施：①移除全部键盘加速器（宿主 Grid、OnAcceleratorInvoked、菜单项 DEL accelerator 与 DEL 文本）——空格/方向键/DEL 同机制同病（焦点被窗口控件持有时加速器被其内部处理抢先，实测无法可靠工作），键盘路径整体放弃；②恢复 `StageRoot.Tapped=OnStageTapped`（单击画面播放/暂停）；③中央播放按钮的 Tapped 拦截是防冲突关键——按钮点击 Handled 后不冒泡到舞台，仅 Click 触发一次 TogglePlayPause（此前「暂停后无法继续播放」实为点击落在按钮之外画面区域所致，属预期行为，已向用户说明）；④清理焦点补丁（OnLoaded Focus、PointerPressed 归位）与 Windows.System using。
