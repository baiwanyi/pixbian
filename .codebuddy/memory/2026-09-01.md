## 骨架屏淡入：探针 ImageOpened 后延迟一渲染帧（继续优化 B 方案）

### 背景
上一轮（2026-08-31）已确认闪烁根因：`ImageBrush` 无「可绘制」信号，改用透明探针 `Image` 的
`ImageOpened` 作门闩，闪烁大幅改善。但用户反馈「没有渐变的效果 + 偶发闪一下」。

### 分析（本轮根因）
探针 `ImageOpened` 只保证**探针 Image 自身**可绘制。探针与 ImageBrush 虽共享同一 BitmapImage
（纹理只解码一次），但 **ImageBrush 的纹理上传到 GPU 可能比探针晚一渲染帧**。立即播放动画时，
动画前段淡入的是空白（ImageBrush 无纹理），纹理就绪瞬间图片突现 —— 观感即「无渐变 + 偶发闪」。

### 实施（仅 ThumbnailPresenter.cs）
- 新增 `PlayFadeInNextFrame()`：`CompositionTarget.Rendering` **单次订阅**，下一渲染帧回调后立即解除。
  回调内校验 `State==Loaded && _imageOpened` 才 `ShowImageWithFadeIn()`（等待期间可能滚走/失败）。
- 两条淡入路径统一走 `PlayFadeInNextFrame()`：
  ① `OnImageOpened` 消费 `_pendingFadeIn` 时；② `ApplyVisualState` 中 `isSkeletonToImage && _imageOpened` 直接路径。
- 新增 `CancelPendingFrame()`：`DataContextChanged`/`Unloaded` 时解除未触发的 `Rendering` 订阅，
  防止容器复用后残留回调误触发。
- 字段 `_pendingRenderFrame` 防重复订阅。

- `dotnet test Pixbian.sln`：**通过**（160 个：Core 115 / WebServer 33 / Imaging 12）

- 用户实测（待反馈）：应看到骨架 → 图片 250ms 渐变，无突现感

### 教训
- **Image 控件的 ImageOpened 与其享 BitmapImage 的 ImageBrush 渲染不同步**：前者只保证自身
  可绘制，后者纹理上传可能晚一帧。共享资源的两条渲染路径就绪时机需分别考虑。
- 等「下一渲染帧」用 `CompositionTarget.Rendering` 单次订阅（回调即退订），比固定延迟更精确、
  无魔法数；但必须配套 `CancelPendingFrame` 处理容器复用/卸载。

## 淡入时长调整 250→400→500ms
- 用户实测 250ms/400ms 渐变感仍不足，最终定 500ms（`FadeInDuration`，`ThumbnailPresenter.cs`）。

## 完整排查链

### 主排查：8 轮（2026-08-31 完成，根因在第 8 轮）

| 轮次 | 用户反馈 | 根因 | 修复 |
|---|---|---|---|
| 1 | 从骨架到图片有抖动 | 骨架填满容器 vs 图片 Uniform 渲染区，形状不匹配 | 骨架按 Uniform 算法定尺寸 |
| 2 | 一闪一闪 | 升级加载把已显示图片打回骨架 | `Thumbnail is null` 才置 Loading |
| 3 | 完成显示后还闪 | 跃迁判据过宽（容器复用串味） | 判据改为「上一次是 Loading」+ DataContextChanged 清理 |
| 4 | 还闪 | 自适应视图首帧按正方形请求 → 升级必现 | 按宽高比估算首帧尺寸 |
| 5 | 还闪 | 淡入先于 Source 设置（空淡入） | 挂起等 Source |
| 6 | 还闪 | `GoToState(Loaded)` 抢在 Source 前 → 双透明空白帧 | Source 未就绪时保持骨架，同帧切换+淡入 |
| 7 | 还闪 | 位图解码异步，淡入的是未解码位图 | 等 `PixelWidth>0` / 位图级 ImageOpened |
| **8** | **还闪（最终根因）** | **信号源级别错：位图级 ≠ 控件级「可绘制」** | 透明探针 Image 的 `ImageOpened` 作门闩 |

**第 8 轮的关键洞察**：`BitmapImage.PixelWidth>0` 只表示 CPU 解码完成；纹理上传 GPU 在其后异步进行，
且服务层返回的位图早已解码、位图级 `ImageOpened` 已错过。`ImageBrush` 本身无「可绘制」信号。
唯一可靠信号是 **`Image` 控件的 `ImageOpened`**（控件级，无论是否缓存都触发）。
因 WinUI 3 的 Image 无 CornerRadius，最终采用 **ImageBrush 显示 + 透明探针 Image 拿信号** 的双层结构。

## 最终行为（验收标准）
- 加载中：浅灰呼吸骨架（深浅主题各一色，形状与图片渲染区严格对齐）
- 加载完成：等纹理真正可绘制（探针 `ImageOpened` + 下一渲染帧）后，骨架与图片交叉淡入 **500ms**
- 加载失败：回退错误图标
- 取消 / 滚出视口：维持骨架，**不**误报为失败
- 容器复用、滚回已加载条目：只重设终值，**不**重播淡入（防滚动时反复闪）
