## 与 v1 的关键差异（审计结论）

v1 的根因定性（R1–R7）经逐条代码核对**全部属实**，整体技术路线（照片应用范式、`ItemsRepeater + VirtualizingLayout`）保持不变。v2 修正以下问题：

1. **验证判据修正**：`THUMBSUBMIT` 实际序列是 **200 → 300 → 500 → 700 → 900**（每页 = 置空数 + 200），v1 判据"200→400→600"是无瘦身的假想序列，照它会误判 R1。
2. **P0-1 骨架屏漏洞**：非虚拟化面板容器生成后**永不回收重建**，`ContainerContentChanging` 仅在容器 realize 时触发一次（`GalleryPage.xaml.cs:302-331`）——被头部瘦身置空的条目，除了 R1 的全量扫描**没有任何其他重解触发点**。v1 的「P0-1 改 `pending = added`」单独实施会让历史条目永久停在骨架屏。v2 将 v1 中属于 P0-3 长期项的「行偏移表」提前到 P0，作为「恢复触发」与「取消窗口化」的共同地基，P0 四步改为**强耦合整组落地**。
3. **P0-2 残留矛盾**：v1 正文 7.1 仍推荐方案 B（异步日志），与决策记录 A（彻底删除）矛盾。v2 统一为删除。
4. **P1b 驱动机制**：v1「按帧预算提交」未指明驱动方式；本项目已实证 `CompositionTarget.Rendering` 不可用（令布局 pass 永久停摆，`GalleryViewModel.cs:761-764` 已永久移除），v2 明确改用 `DispatcherQueueTimer`。
5. **P1a 震荡防护**：v1 动态 `ItemWidth` 未评估「滚动条出现/消失 ↔ 宽度变化」震荡（`JustifiedPanel.cs:83-85` 实证过），v2 增加迟滞防护。
6. **P1b LRU 回调线程亲和**：`MemoryCache` 驱逐回调在线程池触发，置空绑定属性须回 UI 线程，v1 未提。
7. **P2 枚举修正**：v1 示例中 `ElementRealizationOptions.RecycleElement` 不存在（实际只有 `None / ForceCreate / SuppressAutoRecycle`）。

## 一、问题定性（已逐条代码核实）

| 编号 | 根因 | 证据位置 | 核实结论 |
|---|---|---|---|
| R1 ★★★ | 翻页把全部历史条目重新提交解码 | `GalleryViewModel.cs:864`（全量 pending）× `:839-846`（头部瘦身置空） | 属实。提交序列 200→300→500→700→900，第 10 页单次提交 1900 条 |
| R2 ★★★ | 双视图零虚拟化（非虚拟化 Panel + 外层 ScrollViewer） | `GalleryPage.xaml:588-703 / 706-823`；`JustifiedPanel.cs:38` | 属实。容器生成后永不回收，每条目视觉树 60+ 元素（CheckBox 模板展开后比 v1 估算的 30~40 更多） |
| R3 ★★ | 滚动停止全量 × 线性查找 O(n²) | `GalleryPage.xaml.cs:910-940` | 属实。`_lastScanOffsets` 判重对正常滚动无效 |
| R4 ★★ | 诊断日志同步 IO + 全局锁 | `Diagnostics.cs:27-31` | 属实。每条缩略图 3 行（`DISK|THUMB|BITMAP`），且 `LOAD/PROBE/THUMBSUBMIT/LOADTOTAL` 等埋点直接卡 UI 线程 |
| R5 ★★ | measure 副作用 + O(n) 订阅同步 | `JustifiedPanel.cs:96 / :143` | 属实。VM 层 1px 容差已部分缓解实际解码触发，结构性问题仍在 |
| R6 ★★ | 内存口径打架 | `GalleryViewModel.cs:49`（300 条）vs `App.xaml.cs:155`（200MB） | 属实。VM 直持 `BitmapImage` 引用，300 条 VM 引用是常驻下限 |
| R7 ★ | 集合/订阅/字典无界增长 | 多处 | 属实。`_dimensions` 每条仅 2 int，量级轻微 |

**关键补充**：非虚拟化面板容器不回收 ⇒ 被瘦身条目的「滚回重解」目前**唯一依赖 R1 全量扫描**。任何去掉全量扫描的改动必须配套视口驱动的恢复机制。

## 二、成熟应用借鉴（落到具体机制）

| 对标 | 借鉴机制 | 落点 |
|---|---|---|
| Windows 照片应用 | 先建全量行几何表，视口索引驱动 realize 与加载 | P0 行偏移表 → P2 `VirtualizingLayout` |
| 文件资源管理器 | 优先级队列：可见项插队、离开视口取消 | P1b `ThumbnailLoadScheduler` |
| Google Photos | 窗口化（视口 ±1 屏）、按最后使用时间 LRU | P1b 窗口与 LRU 淘汰 |

明确不抄：Lightroom（导入 + 智能预览预算）、Electron/Qt 栈实现、照片应用的时间线 / 人物聚类 / AI 搜索等产品功能。

## 三、平台约束（本项目实证，方案设计硬边界）

1. **`CompositionTarget.Rendering` 禁用**——与渲染 tick 抢占执行窗会令布局 pass 永久停摆（`GalleryViewModel.cs:761-764` 已实证并永久移除）。P1b 的「按帧预算」一律用 `DispatcherQueueTimer` 或解码完成回调驱动。
2. **`SoftwareBitmapSource` 不可用**（fail-fast `0xC000027B`），显示管线保持 `BitmapImage`。
3. **滚动条出现/消失会改变 availableWidth**（`JustifiedPanel.cs:83-85` 实证震荡）——凡「按可用宽度反算条目尺寸」的改动（P1a）必须做迟滞防护。
4. **`ElementRealizationOptions` 只有 `None / ForceCreate / SuppressAutoRecycle`**，无 `RecycleElement` 值；回收靠超出 RealizationRect 自动回收或显式 `context.RecycleElement(el)`。
5. **WinUI 2.3.6 无 `IScrollInfo`、无 `SelectionModel`** ⇒ 自定义 `VirtualizingPanel` 不可行；换 `ItemsRepeater` 必须自建选择服务。
6. **`MemoryCache` 驱逐回调在线程池触发**，置空绑定属性须回 UI 线程。
7. XAML 编译期不校验颜色/枚举字面量；API 存在性一律以包内 `Microsoft.WinUI.xml` 为准（v1 附录 B 的取证结论继续有效）。

## 四、执行方案

### 阶段 0：验证（约 0.5 天，用现有埋点，先于一切改动）

操作步骤沿用 v1 第十二章（归档日志 → Release 启动 → 连翻 5 页 → 分析脚本），**判据修正如下**：

| 实验 | 操作 | 判据（v2 修正） |
|---|---|---|
| R1 | 连续翻 5 页，看 `THUMBSUBMIT` 序列 | **200 → 300 → 500 → 700 → 900**（每页 = 置空数 + 200；呈超线性即为确认） |
| R2 | `PANEL` 采样 | `children` 单调涨到已加载条数且**从不回落** |
| 综合 | `LOADTOTAL` 首尾对比 | last 明显大于 first |
| R4（可选） | `Diagnostics.Log` 首行临时 `return;` 做 A/B 对照 | `LOADTOTAL` 显著变快即确认；跑完还原 |

验证通过后**立即执行 P0-5（删除埋点）**，此后改用工作集观察 + 截屏目检 + `dotnet-stack`。

### 阶段一 P0：止损（约 1~1.5 人日，五步强耦合，须整组落地）

> ⚠️ **整组约束**：P0-2（去掉全量扫描）必须与 P0-1（行偏移表）、P0-3（恢复机制）同批提交，单独实施 P0-2 会引入「历史条目永久骨架屏」回归。

#### P0-1　暴露行偏移表（新增，约 30 行，低风险）

`JustifiedPanel` measure 时已产出 `_rows`（含 `OffsetY` 与成员索引），补充两个只读属性与一个二分查询：

```csharp
/// <summary>每行起始 Y 偏移（长度 = 行数 + 1），measure 后有效。</summary>
internal IReadOnlyList<double> RowOffsets => _rowOffsets;
/// <summary>每行首个条目的数据索引（长度 = 行数）。</summary>
internal IReadOnlyList<int> RowStartIndices => _rowStartIndices;
/// <summary>按 Y 区间二分求覆盖的数据索引区间。</summary>
internal (int First, int Last) IndexRangeFromY(double top, double bottom);
```

measure 期间顺手增量填充两个列表，不增加测量复杂度。方形视图行高均匀，直接 `offset / rowHeight` 除法即可，无需面板配合。

#### P0-2　`pending` 只取本页新增 + 被瘦身条目登记（修正 R1）

```csharp
var added = new List<MediaItemViewModel>(page.Count);
// reset / 追加两分支：逐条 new MediaItemViewModel 并记入 added
// 头部瘦身处：置空 Thumbnail 的同时加入 _evicted（HashSet<MediaItemViewModel>）
pending = added;
```

- `_evicted` 条目在重新解码成功后移出；
- `SetThumbnailSizeAsync` / `RefreshThumbnailsAsync` 的全量语义保留，但只对 `Items` 当前集合提交（其规模 = 已加载数，可接受；P1b 后改经调度器）；
- 已知小回归：解码失败条目（`State=Failed`）失去「下次翻页顺带重试」的隐性机制，改为滚回视口时经 P0-3 窗口恢复一次。

#### P0-3　滚动事件改为「视口区间驱动」（同时修复 R1 恢复与 R3）

`OnScrollViewChanged`（非 intermediate 时）：

1. 经行偏移表二分求当前可见索引区间 `[first, last]`，扩展 ±1 屏条目数为窗口；
2. **恢复**：窗口内落在 `_evicted` 的条目 → 重新提交 `EnsureThumbnailAsync`（批量 ≤ 一屏，走现有 10 条/40ms 批节奏），并从 `_evicted` 移除；
3. **取消**：仅对「上次窗口 ∪ 本次窗口」差集中 `ContainerEverRealized` 的条目 `CancelPendingLoad()`——彻底消灭全集合 × `ContainerFromItem` 扫描；
4. `CancelOffscreenThumbnails` 原实现与 `_lastScanOffsets` 判重删除。

#### P0-4　订阅同步改脏标记（修正 R5）

`Children.Count` 变化或容器换数据时置 `_subscriptionsDirty`，measure 仅在 dirty 时重建订阅；`HashSet.Except` 每帧分配随之消失。

#### P0-5　删除 `Diagnostics` 类及全部埋点

涉及 `Diagnostics.cs`、`GalleryViewModel.cs`、`ThumbnailService.cs`、`GalleryPage.xaml.cs`、`JustifiedPanel.cs`、`App.xaml.cs`；顺带清理 `ThumbnailService.cs:245-251` 重复的取消检查段。

**P0 验收**：

- 连翻 5 页，解码提交数恒定 ≈200；
- 向上滚回第 1 页，缩略图在窗口内恢复显示（不允许永久骨架屏）；
- 失败条目滚回视口可恢复；
- 快速滚动无 `ContainerFromItem` 扫描卡顿；
- `dotnet build -warnaserror` 0 警告。

### 阶段二 P1a：方形视图原生虚拟化（约 1 人日，低风险）

1. 删除 `GridViewView` 外层 `ScrollViewer`，`GridView` 自滚（`ItemsWrapGrid` 才能拿到真实视口）；
2. `ItemsPanel` 换 `ItemsWrapGrid`，`SquarePanel` 退役（同步更新 `GalleryPage.xaml` 头注释中「方形视图用内建 ItemsWrapGrid」的过时说明——现状代码实为 `SquarePanel`）；
3. 触底翻页迁到 `OnGridViewControlLoaded` 已订阅的内部 ScrollViewer（该路径在现状布局下从不触发，迁移后自然生效）；
4. 动态格子边长按 v1 公式，**追加迟滞防护**：

```csharp
// 宽度变化不足一个间距时不重算 ItemWidth，阻断「滚动条出现/消失 ↔ 宽度变化」循环
if (Math.Abs(availableWidth - _lastLaidOutWidth) < spacing) { return; }
_lastLaidOutWidth = availableWidth;
```

5. 容器回收重建后，`ContainerContentChanging` 对回收条目再次触发 ⇒ 方形视图的「滚回重解」恢复机制**自动成立**，P0 的 `_evicted` 路径对方形视图可退役。

**P1a 验收**：2000 条时容器数恒定（数百级）、视觉树元素数百级；选择/右键/双击/hover 复选框零回归；快速拖动滚动条无白屏与震荡。

### 阶段三 P1b：解码调度器 + 位图 LRU（约 2~3 人日，核心）

#### `ThumbnailLoadScheduler`（新建）

```csharp
public sealed class ThumbnailLoadScheduler : IDisposable
{
    /// <summary>视口区间更新：重算窗口（视口 ±1 屏）、按「距视口中心距离」优先级入队、取消离窗在途项。</summary>
    public void UpdateViewport(int firstVisibleIndex, int lastVisibleIndex);
    /// <summary>档位/缩放比变化：保留全量重解语义，但按窗口渐进提交。</summary>
    public Task RefreshAsync(IReadOnlyList<MediaItemViewModel> items);
    /// <summary>切视图/筛选：清队列、取消全部在途。</summary>
    public void Reset();
}
```

实现要点：

| 要点 | 做法 |
|---|---|
| 并发 | 沿用 `ThumbnailService.DecodeConcurrency` 信号量 |
| UI 提交节奏 | `DispatcherQueueTimer`（约 33ms tick，每 tick ≤4 个位图创建）替代批 10 + 40ms；**禁用 CompositionTarget.Rendering（平台约束 1）** |
| 取消 | 离开窗口 `CancelPendingLoad()`，代价 O(窗口)；沿用「只取消不释放 CTS」约定 |
| 去重 | 沿用 `_inflightSize` 只升不降 + `UpgradeTolerance` |
| 失败 | `State=Failed` 条目不自动重试，仅重新进入视口时经窗口提交恢复一次 |

#### 位图 LRU（替换头部瘦身）

- 废弃 `MaxResidentThumbnails` 按索引回收；以 `SizeLimit=200MB` 为唯一口径；
- `PostEvictionCallback` 中**经 `DispatcherQueue` 回 UI 线程**置空 `Thumbnail`、打 `IsEvicted`（平台约束 6）；置空前校验「VM 当前引用 ≠ 被淘汰位图」避免竞态；
- `IsEvicted` 必须与「从未加载」区分：被淘汰项仅**进入视口**时才重新解码，不参与预取——打断「释放 → 重解 → 再释放」自激循环；
- `ThumbnailDiskCache`（LRU 2GB）与 `Release` 只清内存的设计保持不变。

**P1b 验收**：解码请求数 = O(视口)；工作集（2000 条）< 400MB；快速滚动时近视口缩略图先出（优先级生效）；滚动回看无闪烁（LRU ≥ 3 屏 + 磁盘秒回）。

### 阶段四 P2：自适应视图 `ItemsRepeater` + `JustifiedVirtualizingLayout`（约 5~8 人日）

1. 贪心分行算法 1:1 迁入 `VirtualizingLayout.MeasureOverride`（先建全量行几何表，再按 `RealizationRect` 二分 realize）；
2. 元素获取用 `context.GetOrCreateElementAt(index)`（**默认选项**，超出 RealizationRect 自动回收；需要跨 pass 保留时才传 `SuppressAutoRecycle`——v1 示例中的 `ElementRealizationOptions.RecycleElement` 不存在，勿照抄）；
3. 未测量行按 `RowHeight` 估算参与 extent，行偏移表失效期间防抖动；
4. `GallerySelectionService`（基于索引）：单击 / Ctrl / Shift / 全选 / 清除 + `SelectionChanged`；宿主侧用 `ElementPrepared` 挂绑定、`ElementClearing` 解绑、`GetElementIndex` 命中测试；迁移 hover 复选框浮现、右键菜单、双击、键盘导航（自建容器模板 + VisualState 视觉）；
5. 两视图并存观察期：方形继续 GridView，自适应切 Repeater，逐项回归选择/收藏/删除/重命名路径。

**P2 验收**：双视图容器数恒定；任意位置拖动滚动条 < 16ms 帧感（目检）+ 无白屏闪烁；选择模式全路径回归通过。
