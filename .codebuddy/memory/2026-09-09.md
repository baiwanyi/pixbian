## 等高视图多选错位修复（未提交，4 文件）
- 现象：等高模式点 checkbox 能选中并进入选择模式；再点其他**图片**就退出选择模式（外框全消、选中态“还在”、悬停才看得见）；多点几次后点图片与点 checkbox 都退出。方形模式正常。
- 根因（两条叠加）：
  1. 等高布局 Arrange 只排本 pass realized 的元素；已滚出但 Repeater 尚未回收的元素（幽灵槽位）仍停留在旧矩形并继续参与命中测试，点图片主体命中它们 → `ResolveHit` 沿树取到**旧条目** DataContext → `Toggle` 了不属于当前集合的游离条目。
  2. `GallerySelectionService.SelectedItems = _selected ∩ Items`，游离条目进入 `_selected` 后交集恒空 → `HasSelection=false` → 每一次 SelectionChanged 都走 `ExitSelectionMode`（这就是“点什么都是退出”的唯一出口）。
- 修复：
  - `JustifiedVirtualizingLayout`：新增 `PreviousElements` 映射与 `SwapRealizedElements()`；Arrange 前把「上一 pass 有、本 pass 无」的元素 `Arrange(default)` 收拢到零矩形（**不碰 Visibility**——Repeater 元素运行期改它必 fail-fast 0xc000027b）。
  - `GalleryPage.ResolveHit` / `OnJustifiedCheckClick`：改以 `JustifiedRepeater.GetElementIndex(element)` 反查集合为唯一真相源，DataContext 仅作“元素已失去映射”时的兜底；`ResolveHit` 由 static 改实例方法。
  - `GallerySelectionService`：新增 `PruneStale()`（剔除游离条目并复位其 IsSelected），`Toggle` 遇到不在当前集合的条目直接忽略。
  - 等高 CheckBox 的 `Opacity` 改绑 `IsSelectionCheckVisible`（复用已定义但闲置的 `BoolToSelectionOpacityXBind`），删除 `SyncJustifiedCheckOpacity()` 视觉树快照补写；`ElementPrepared` 回调就地补 `IsSelectionCheckVisible`（覆盖分页/滚动新条目）；`ExitSelectionMode` 按当前集合全量复位 `IsSelected`（清残留勾）。
- 构建：`-c Release -warnaserror` → 0 警告 0 错误（50s）。
- 结果：**用户手工验证通过（等高多选恢复正常）**；取证埋点 `HIT|idx=|ctx=` 已删除并重新构建 → 0 警告 0 错误（31s）。
- 复盘要点：本次「点图片退出选择模式」这类症状，与其逐个调交互分支，不如先找**退出选择模式的唯一出口**（`HasSelection=false`）再倒查为何判空——选择集合用「交集」语义时，游离条目会让判空恒真，这是自建选择服务的通用陷阱。

## 等高视图翻页被弹回顶部（未提交，2 文件）
- 现象：等高模式滚到底部触发翻页后被弹回顶部，看不到新加载内容（数据其实加载了）。
- 根因：`GalleryViewModel` 的翻页追加 / 集合替换 / 删除**三条路径共用 `ItemCount` 通知**，而页面把「回顶 + 重建元素」挂在 ItemCount 上 → 翻页后 `RebuildJustifiedElements()` 强制 `ChangeView(null,0,…)`。方形视图的回顶挂在 `IsQuerying` 分支（只有 reset 置 true），故只有等高模式中招。删除路径同样误回顶。
- 修复：VM 新增 `ItemsReplaced` 事件（仅 `ReplaceItemsCore` 触发），页面把 `RebuildJustifiedElements` 的触发源从 ItemCount 换成该事件；ItemCount 通知保留（仍驱动统计行 / 空状态 / 复选框同步）。教训：**语义型通知（回顶/重建）不能挂在共用计数通知上**，事件名即语义。
- 构建 `-c Release -warnaserror` → 0 警告 0 错误（32s）。待用户手工验证连续翻页滚动位置稳定。
- 结果：用户手工验证通过（翻页滚动位置稳定）。

## 等高视图选中后 DEL 键无效（未提交，2 文件）
- 现象：等高模式选中若干条目后按 DEL 无反应。
- 根因：`RestoreContentFocus` 给等高宿主 `JustifiedView`（ScrollViewer）做 `Focus(Programmatic)`，但 **WinUI 的 ScrollViewer 默认 IsTabStop=False → Focus 静默失败**；模式切换时框架已把焦点自动转移到搜索框，DEL 被文本编辑消费，页面 KeyDown 收不到。P2 把等高宿主从 GridView（IsTabStop=true，聚焦成功）换成 ScrollViewer+ItemsRepeater 引入的回归；方形模式 GridView 聚焦成功故正常。
- 修复：XAML 给 `JustifiedView` 加 `IsTabStop="True"`；`RestoreContentFocus` 注释写明该前提（不检查 Focus 返回值是有条件的）。
- 构建 → 0 警告 0 错误（41s）。待用户手工验证。
- 结果：焦点修复生效（F2/Ctrl+A 能到页面），但 DEL/Ctrl+C/Ctrl+D/Esc 仍"无效"。KEY 埋点取证：**所有键都到达页面且 targets 非空** → DEL 实际执行了删除（Ctrl+A 全选 397 = 400−3 铁证），但**删除路径 `JustifiedSelection.Remove` 不触发 `SelectionChanged`** → 页面 Selection 缓存停留在已删条目 → 删除零反馈 + Ctrl+C 拿过期列表复制已删文件（异常被 fire-and-forget 吞）+ Ctrl+D/Esc 清空集（Clear 提前 return）全部静默无效。
- 修复：`GallerySelectionService.Remove` 在真移除选中项时触发 `SelectionChanged`（页面实时刷新 Selection、空选择自动退出选择模式）；`CopyItemToClipboardAsync` 改实例方法 + try/catch 弹错误对话框（fire-and-forget 异常不再静默）。KEY 埋点已删。
- **新增长期事实候选**：① WinUI 的 ScrollViewer 默认 IsTabStop=False，`Focus(Programmatic)` 静默失败——凡「把焦点还给 ScrollViewer」的代码必须先确保 IsTabStop=True；② 自建选择服务里，**除页面交互外的任何选中集合变更（如删除联动）都必须触发 SelectionChanged**，否则页面缓存的选择列表过期，后续快捷键全部操作幽灵条目且零反馈；③ fire-and-forget 的复制/删除类操作必须自带 catch 反馈。
- 结果：用户验证除 Ctrl+C 外全部通过（Ctrl+C 用户明确放弃修复）。剩余问题：DEL/Ctrl+D/Esc 后焦点被强设到列表框。
- 焦点还原条件化（1 文件）：`RestoreContentFocus` 加 `IsFocusWithinPage()` 前置判断——焦点仍在本页视觉树内（如刚点过的复选框）时不抢，仅焦点丢失/被框架转移到页面外时还原。判定用 `FocusManager.GotFocus` 全局事件跟踪 `_lastFocusedElement`（**GetFocusedElement 在键处理栈内返回 null 的怪癖不可靠**，KEY 埋点实证）；GotFocus 订阅随 Loaded/Unloaded 对（静态事件持引用）。坑：`FocusManager.GotFocus` 委托是 `EventHandler<FocusManagerGotFocusEventArgs>` 而非 TypedEventHandler（CS0123 会连锁引发 XAML 假错误，先修 CS）。构建 0 警告 0 错误（37s）。
- 结果：**用户验证全部通过**。今日四个修复（等高多选错位、翻页回顶、DEL 焦点链、删除选择失同步 + 条件焦点还原）共 5 个源码文件，未提交。
