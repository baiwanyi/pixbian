## 方形网格改为行填满布局（GalleryPage）
- 需求：方形模式格子不拘泥固定尺寸，每行填满内容区宽度，条目保持 1:1；图片内容显示维持上轮 `Stretch=None`（原尺寸居中，经确认）。
- 根因：`ItemsWrapGrid` 固定 `ItemWidth/ItemHeight`，行末残留空隙且无 `Spacing`，无法精确填满行宽。
- 实现：新增 `SquarePanel`（`JustifiedPanel` 的正方形简化版）——测量时按可用宽与目标边长（`GridItemWidth` = 档位 + 间距）四舍五入推导每行个数，`edge = (可用宽 − Spacing×(n−1)) / n` 均匀放大填满行宽；回写 `SetDisplaySize(edge, edge)`（VM 容差去重防反复解码）；测量行参数缓存供 Arrange 复用。`GalleryPage.xaml` 方形视图 `ItemsPanelTemplate` 换 `SquarePanel ItemSize="{Binding GridItemWidth}" Spacing="8"`，`MediaItemTemplate` Border 去 `Margin="0,0,8,8"`，删孤立 `xmlns:winui`。
- code-behind 未改：`OnContainerContentChanging` 的首帧回写 `(ThumbnailSize, ThumbnailSize)` 仍作正方形兜底，面板精确回写与档位量化下基本不触发多余重解码。
- 权衡：`SquarePanel` 不做 UI 虚拟化（与 `JustifiedPanel` 同一权衡，靠分页增量加载控制规模）。
- 验证：`dotnet build` 0 警告 0 错误。
- 涉及文件：`src/Pixbian/Controls/SquarePanel.cs`（新增）、`src/Pixbian/Views/GalleryPage.xaml`。

## 图库列表性能诊断与方案（未改代码，仅出方案）
- 现象：列表越加载越卡、资源占用随条目数增长。诊断后落盘 `docs/图库列表性能优化方案.md`（含根因清单、对标分析、执行方案、验收标准）。
- 根因（按贡献排序）：R1 `GalleryViewModel` 翻页时 `pending` 取全集合、与「头部瘦身 300」叠加成自激循环（第 N 页提交约 200N 条解码，**主因**）；R2 两视图零虚拟化（自定义 `Panel` + 外层 ScrollViewer 包裹，后者即使换虚拟化面板也失效）；R3 `CancelOffscreenThumbnails` 全集合 × `ContainerFromItem` 线性查找 = O(n²)；R4 `Diagnostics.Log` 同步 `File.AppendAllText` + 全局锁，每条缩略图写 3 行；R5 `JustifiedPanel` 每次 measure 重建订阅 HashSet 且在 measure 内发起解码；R6 位图按索引回收（300）与 `SizeLimit` 200MB 口径不一且与 R1 互激；R7 集合/订阅无上限。
- 对标结论：主参考 **Windows 照片应用**（同栈同版式同约束，且 `JustifiedPanel` 分行算法可 1:1 保留，只换底座），辅以文件资源管理器的解码优先级队列，思想借鉴 Google Photos；明确不参考 Lightroom（其性能建立在「导入即生成智能预览」的预算上）。
- 待用户拍板：① 是否立即执行 P0 四项；② 诊断日志走「彻底删除」还是「异步改造+默认关闭」（推荐后者）；③ P2 推进节奏（推荐「分两段」：先 P0+P1a+P1b 约 4 天）。
- 涉及文件：`docs/图库列表性能优化方案.md`（新增）。
