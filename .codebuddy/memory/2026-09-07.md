## 切换模式无过渡的根因修复（日志实证）
- 用户确认视频正常、图片无过渡 → diag.log 显示其测试时段（15:57 后）**零条 TRANS**：图片切换根本没发起转场请求。

## 「切换模式无过渡」真根因：重写时丢失 OnSourceImageChanged 钩子（决定性）
- 加守卫诊断日志后（skip=/raised），用户实测**连 skip= 都没有** → RequestTransition 从未被调用 → 排查发现 **OnSourceImageChanged partial 方法在第二轮全量重写 SlideShowViewModel 时丢失**。后果链：SourceImage 赋值 → 无 DisplayImage 通知（绑定不更新）→ 无转场请求 → 转场/扩大动画全部死路。视频正常是因为视频层走 CurrentPlaybackItem 通知（独立链路）。

- 已恢复钩子（OnPropertyChanged(DisplayImage) + RequestTransition）并重建启动，待复测。
- 复测确认生效。用户反馈扩大太快 → 终值 1.25→1.2（设置页文案同步）；时长保持对齐放映间隔（间隔即动画时长，想更慢调大间隔）。

## 幻灯片第十二轮：拖尾与边缘闪的真根因（两个都是设计叠加所致）
- 用户实测确认：拖尾有、边缘闪有且是**图片边缘**。
- **边缘闪真因**：溶解时新帧的「推进缩放」(1.04→1.00) 与画面动画 Ken Burns 的缩放**叠加**：以放大类为例合成后从 1.04 先缩到约 1.01，转场结束后画面动画才继续增大到 1.15——**缩放先减后增（非单调）**，图片边缘先内缩再外扩，即那一下抖动。修法：幻灯片调用 `CreateDissolveStoryboard` 时新帧缩放层传 **null**，新帧缩放全部交给画面动画；旧帧仍做 1.0→0.96 后退保留层次。**结论：同一层的缩放只能由一个动画源驱动，转场缩放与 Ken Burns 必须二选一。**
- **拖尾真因**：上一轮为防「亮度塌陷」让旧帧保持不透明托底到 75% 再淡出 → 旧图「一直在、迟迟不走」。但**有了虚化背景后，两层同时半透明露出的是模糊背景而不是黑底，塌陷不复存在** → 改回交叉淡化（旧帧 1→0 与新帧 0→1 同步全程）。这一改同时解决拖尾与「转场后残留」：转场结束时旧帧本就透明，直接清空无残留。删除 `CreatePreviousTailFade` 与尾段逻辑。
- **前提反转记录**：「旧帧必须托底防塌陷」这条只在**纯黑舞台**下成立；引入虚化背景后该约束失效，交叉淡化恢复为正确解。
- 涉及文件：`TransitionAnimationFactory.cs`、`SlideShowPage.xaml.cs`、`ImageViewerPage.xaml.cs`（后两者同步新签名）。构建 0 警告 0 错误，已启动（PID 20024）。仍未提交。

## 幻灯片第十四轮（架构重构）：合成帧机制——对齐 Windows 照片的真实呈现方式
- 用户点破 Windows 照片幻灯片的机制：**先把「照片 + 以它为素材的虚化背景」合成一张舞台等大的画面，Ken Burns（放大缩小左右移动）作用于这张合成图**。此前"前景动、背景静止"的分层方案从结构上就错位——前景缩放时边缘在视口内移动（竖图黑边变化），必然闪烁。

## 幻灯片第十六轮：转场旧帧不写死起点 + Ken Burns 后置 + 装载覆盖层
- 实测反馈：合成帧观感 OK、Ken Burns 平滑无边缘抖动（合成架构生效）；但滑动/溶解切换时「图片还原为原始位置和状态」有抖动，淡出模式 OK。
- **根因**：转场动画把旧帧轨道起点**写死**（滑动平移 From=0、溶解缩放 From=1.0），而移交过去的 Ken Burns 终态（缩放可能 1.0–1.08、平移 ±1.5%）被强制打回原点 → 切换瞬间跳回原始状态。修法：工厂里旧帧轨道一律 **`from = null`（从当前值继续）**——滑动旧帧从当前位置继续滑出、溶解旧帧从当前缩放平滑过渡到让位倍率 `DissolvePreviousScale = 1.04`（原 `DissolveExitScale = 0.98` 缩小语义废弃，旧帧改放大让位）。
- **Ken Burns 后置**：原先转场开始即启动画面动画，会与滑动转场的平移复位相互拉扯（转场把 pan 拉回 0，画面动画又推出去）。改为**转场 Completed 后才启动**（Windows 照片同样是转场完成才开始运动）；进度条仍在转场开始起算（对应停留时间）。
- **装载覆盖层**（用户提议、评估后采纳）：点击放映立即全屏黑 + ProgressRing，首帧合成完成后撤下。`LoadingLayer`（IsHitTestVisible=False 让点击穿透到帧层）；BeginOpen 显示、PresentFrameAsync 首帧合成完成后隐藏——大图合成数秒期间不再是无反馈黑屏。

## 幻灯片第十七轮：开始/结束跳变的两个真伤（覆盖失效 + 初值跳变）
- 反馈：图片开始和结束都跳变。
- **真伤一（移交被覆盖）**：`PresentFrameAsync` 先 `HandOverToPrevious()`（旧帧 = 显示帧的缩放/平移终态），随后 `ResetFrameTransforms()` 把**两帧**（含旧帧）全部归位——移交值被覆盖，旧帧在切换瞬间跳回原始位置和大小。修：复位方法收窄为 `ResetDisplayFrameTransforms()`（只动显示帧），旧帧终态不可碰。**教训：凡是"移交终态"模式，复位范围必须排除被移交方。**
- **真伤二（初值跳变）**：ZoomOut/平移类的 Ken Burns 起始值不是 1.0（如 1.08 或 1.04+±pan），而转场期间新帧处于复位态 1.0 → 动画启动瞬间跳到起始值。修：**运动形态在呈现时随机决定，淡入期间画面就处于该形态的初值上**（`ApplyMotionInitialState`），画面动画一律 `from=null` 从当前值推进到终值——起止两端连续。`StartKenBurns` 不再随机（用 `_currentMotion`），`ApplyPanBaseScale` 删除。
- 通用结论：**动画链条上任何一段写死起点（from=0/1.0）都会在链上制造跳变**；整条链（移交 → 淡入 → 画面动画）统一 from=null、由"设置初值"的一方负责起点。

## 幻灯片第十八轮：切换开始跳变 = 移交晚于 Stop（同一条教训第三次踩）
- 反馈：照片结束准备切换时跳变。真因：`PresentFrameAsync` 里**先 Stop 画面动画、后 HandOverToPrevious**——Stop 解除 HoldEnd 后缩放/平移立刻回落为本地初值，移交拿到的就是回落值，旧帧在切换开始瞬间从放大状态跳回原尺寸。

## 幻灯片第十九轮：移交改线性插值计算（不信任动画属性 getter）
- 反馈仍：每张图切换时还原位置。顺序修复后 HandOver 读到的仍是回落值 → 判定 **WinUI 3 中 Storyboard 动画运行时依赖属性 getter 不保证返回动画插值**（读到的是本地初值）——不实测猜测行为，直接绕开。
- 修法：Ken Burns 是线性运动，起止与时长全部已知 → **按运动参数线性插值直接计算当前状态**（`GetCurrentMotionState`：elapsed/总时长 clamp 后在初值↔终值间插值，与 XAML 动画轨迹一致），HandOver 用计算值移交，`_motionStartedUtc` 在 `ApplyMotionInitialState` 记录。加 `SLIDESHOW|HANDOVER|zoom=|pan=|getter=` 日志对比计算值与 getter 值（验证 getter 是否真的失效）。
- **通用结论**：WinUI 中凡是需要「读动画运行中/HoldEnd 的当前值」做移交或快照，一律按运动参数自行插值计算，不要读依赖属性；getter 行为不可靠且无文档保证。
- 涉及文件：`SlideShowPage.xaml.cs`。构建 0 警告 0 错误，已启动（PID 10344）。仍未提交。
- **实测验证（HANDOVER 日志，getter 不可靠实锤）**：Pan 类运动中 zoom 本地值恒 1.04，getter 读数却在 **1.033 ~ 1.047** 间波动——getter 既不是本地值也不是确定的插值，语义不明。结论固化：**WinUI 3 中动画运行期间读依赖属性 getter 不可信，移交/快照一律按运动参数自行插值计算**。用户确认跳变消除。

## 复选框配色改为随主题：SolidColorBrush + ThemeResource Color（重要机制）
