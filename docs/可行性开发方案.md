## 1. 项目目标与成功标准

### 1.1 目标定义

构建一个替代/增强 Windows 照片应用的本地媒体管理工具，覆盖「媒体库索引 → 浏览 → 编辑 → 分类 → 发现 → 跨设备访问」的完整闭环。核心定位是**本地优先（Local-First）**：所有索引数据、缩略图缓存、用户配置均存储在本机，不依赖任何云端服务。

### 1.2 可量化的成功标准

| 指标类别 | 目标值 | 测量方式 |
|---|---|---|
| 索引吞吐 | 首次全量索引 ≥ 800 文件/秒（本地 SSD） | 10 万文件样本计时 |
| 冷启动到可交互 | ≤ 2.5 秒 | Stopwatch 埋点 |
| 网格滚动帧率 | 稳定 60 FPS（10 万条索引） | Visual Studio 性能探查器 |
| 缩略图命中延迟 | 内存命中 ≤ 1 ms；磁盘命中 ≤ 20 ms | 缓存层埋点统计 |
| 内存占用 | 10 万条索引浏览时 ≤ 600 MB | 任务管理器 / dotnet-counters |
| 视频起播时间 | ≤ 1.2 秒（1080p MP4 局域网内） | 起播打点 |
| 兼容性 | Win10 1809 / Win10 22H2 / Win11 24H2 三平台全部通过冒烟 | 虚拟机矩阵测试 |

对 8 项需求逐条评估技术可行性、实现成本与风险等级。

| # | 需求 | 可行性 | 主要挑战 | 风险 |
|---|---|---|---|---|

| 2 | 视频管理与播放 | **中高** | FFmpeg 包体积与许可合规；硬件解码适配 | 中 |
| 3 | 局域网 Web 访问 | **中高** | 免管理员权限监听；Range 请求；鉴权与只读模式 | 中 |
| 4 | 正则分类管理 | **高** | 正则回溯（ReDoS）防护；批量重算性能 | 低 |
| 5 | 发现模式 | **高** | 随机算法质量与去重 | 低 |
| 6 | 媒体库管理 | **高** | 文件夹监控去抖；符号链接环路；跨卷移动 | 中 |
| 7 | 界面布局 | **高** | WinUI 3 控件成熟度（部分控件缺失需自绘） | 低 |
| 8 | 性能与兼容 | **中高** | Win10 1809 API 降级；大库内存压力 | 中 |

### 4.3 关键选型决策记录（ADR）

#### ADR-001：视频解码采用 FFmpegInteropX

- **决策**：使用 FFmpegInteropX 作为唯一视频解码与元数据引擎。
- **理由**：MP4/MOV/AVI/MKV 及绝大多数编码开箱支持，缩略图抽取与元数据读取可复用同一套 FFmpeg 管线；系统 `MediaPlayerElement` 对 MKV 与 HEVC 的支持强依赖用户机器的解码器安装情况，体验不可控。
- **代价**：包体积增加约 60–100 MB；需附带 LGPL/GPL 许可声明与源码获取说明。
- **替代方案**：系统解码器 + FFmpeg 双引擎回退（兼容性最佳，但实现与维护成本显著上升，M4 阶段若出现兼容性问题再评估）。

#### ADR-002：HEIC 采用系统 HEIF 扩展

- **决策**：通过 WIC（`Windows.Graphics.Imaging` / `BitmapDecoder`）调用系统 HEIF 解码器，不内置第三方库。
- **理由**：零包体积成本；微软「HEIF 图像扩展」是 Store 免费组件，安装门槛低。
- **代价**：用户未安装扩展时无法解码。
- **缓解措施**：应用内检测解码失败 → 展示「安装 HEIF 扩展」引导卡片，一键跳转 `ms-windows-store://pdp/?ProductId=9pmmsr1cgpwg`。

#### ADR-003：HTTP 服务自研 TcpListener

- **决策**：基于 `System.Net.Sockets.TcpListener` 实现极简 HTTP/1.1 服务。
- **理由**：`HttpListener` 监听非 localhost 地址必须事先执行 `netsh http add urlacl` 并需要管理员权限，首次启动弹 UAC 严重损害体验；自研方案双击即用。
- **代价**：需自行实现路由、MIME 映射、Range 请求（视频拖动进度条强依赖）、分块传输。
- **边界**：该服务仅监听局域网，**不实现** HTTP/2、TLS 终止、WebSocket（如后续需要再引入）。

#### ADR-004：数据访问使用 Microsoft.Data.Sqlite 手写参数化 SQL

- **决策**：不使用 EF Core，直接手写 SQL + 全参数化查询，轻量仓储层封装。
- **理由**：EF Core 对桌面应用而言启动开销与包体积不划算；手写 SQL 便于精确控制批量 Upsert、事务与索引策略，且**天然满足「禁止 SQL 拼接」的安全要求**。
- **约束**：所有动态条件一律使用参数化（如 `WHERE (@kind IS NULL OR kind = @kind)`），禁止字符串拼接。

#### ADR-005：发布形态为非打包（Unpackaged）自包含

- **决策**：`WindowsPackageType=None` + `WindowsAppSDKSelfContained=true`。
- **理由**：无需 MSIX 签名证书，可直接 `dotnet run` 调试与 xcopy 部署；Windows App SDK 运行时随应用分发，不依赖用户机器预装。
- **代价**：无应用商店分发能力；安装目录体积较大。若后续需上架 Store，可追加打包项目（不影响现有代码结构）。

## 5. 系统架构

### 5.1 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  Pixbian (WinUI 3 UI)                                      │
│  Views / ViewModels / Controls / Converters / Themes         │
│  ── 依赖 CommunityToolkit.Mvvm，禁止直接写 SQL 或 File I/O ──  │
└───────────────────────────┬─────────────────────────────────┘
                            │ 引用
┌───────────────────────────▼─────────────────────────────────┐
│  Pixbian.Core（领域层，net8.0，可单测）                     │
│  Models / Services / Abstractions / Utilities                │
│  ── 索引、分类规则引擎、发现算法、路径安全 ──                   │
└───────┬───────────────────────────────┬─────────────────────┘
        │ 实现仓储接口                    │ 依赖
┌───────▼──────────────┐  ┌─────────────▼─────────────────────┐
│ Pixbian.Data       │  │ Pixbian.Imaging / .Media        │
│ SQLite 仓储 + 迁移    │  │ 解码 / EXIF / 裁剪 / 视频元数据    │
└──────────────────────┘  └───────────────────────────────────┘
                            ┌─────────────────────────────────┐
                            │ Pixbian.WebServer             │
                            │ TcpListener HTTP + 路由 + 鉴权   │
                            └─────────────────────────────────┘
```

**依赖方向规则（强制）**：

1. `Core` 不依赖任何上层项目，只依赖 .NET BCL 与 `Microsoft.Extensions.Logging.Abstractions`。
2. `Data` 依赖 `Core`（实现其 `Abstractions` 中声明的仓储接口），反向依赖禁止。
3. `Imaging` / `Media` / `WebServer` 依赖 `Core`，彼此之间不相互依赖（需要共享能力时上提到 `Core`）。
4. UI 层可依赖全部下层，但下层禁止引用 UI 层类型。
5. 所有跨层数据交换使用 `Core/Models` 中的模型，禁止下层泄漏 `SqliteDataReader` 等基础设施类型。

## 6. 数据模型设计

### 6.1 表结构（Schema v1）

```sql
-- 媒体条目主表
CREATE TABLE IF NOT EXISTS media_items (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    path          TEXT    NOT NULL UNIQUE,      -- 文件完整路径，唯一键，Upsert 冲突目标
    file_name     TEXT    NOT NULL,             -- 文件名（含扩展名），用于正则分类与搜索
    directory     TEXT    NOT NULL,             -- 父目录，用于按库目录对账与前缀筛选
    kind          INTEGER NOT NULL,             -- 0=图片 1=视频 2=其他
    file_size     INTEGER NOT NULL,
    created_utc   TEXT    NOT NULL,             -- ISO8601 Round-trip 格式
    modified_utc  TEXT    NOT NULL,
    indexed_utc   TEXT    NOT NULL,
    taken_utc     TEXT    NULL,                 -- EXIF/媒体时间，未解析时用 created/modified 较早者兜底
    width         INTEGER NULL,
    height        INTEGER NULL,
    duration_ms   INTEGER NULL,
    is_favorite   INTEGER NOT NULL DEFAULT 0,   -- 用户数据，扫描 Upsert 时不得覆盖
    category_id   INTEGER NULL,
    rating        INTEGER NOT NULL DEFAULT 0,
    deleted_utc   TEXT    NULL                  -- 软删除，避免误删后重新扫描立刻回填
);

CREATE INDEX IF NOT EXISTS ix_media_items_kind      ON media_items(kind);
CREATE INDEX IF NOT EXISTS ix_media_items_taken     ON media_items(taken_utc DESC);
CREATE INDEX IF NOT EXISTS ix_media_items_directory ON media_items(directory);
CREATE INDEX IF NOT EXISTS ix_media_items_category  ON media_items(category_id);
CREATE INDEX IF NOT EXISTS ix_media_items_favorite  ON media_items(is_favorite) WHERE is_favorite = 1;
CREATE INDEX IF NOT EXISTS ix_media_items_size      ON media_items(file_size);

-- 媒体库扫描源
CREATE TABLE IF NOT EXISTS library_folders (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    path          TEXT    NOT NULL UNIQUE,
    display_name  TEXT    NOT NULL,
    added_utc     TEXT    NOT NULL,
    is_enabled    INTEGER NOT NULL DEFAULT 1,
    last_scan_utc TEXT    NULL
);

-- 分类定义（规则命中后归入的「分类」实体）
CREATE TABLE IF NOT EXISTS categories (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL UNIQUE,
    color       TEXT NULL,
    sort_order  INTEGER NOT NULL DEFAULT 0
);

-- 正则分类规则
CREATE TABLE IF NOT EXISTS category_rules (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    name         TEXT    NOT NULL,
    pattern      TEXT    NOT NULL,              -- 正则表达式
    category_id  INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    target       INTEGER NOT NULL DEFAULT 0,    -- 0=文件名 1=完整路径 2=扩展名
    is_enabled   INTEGER NOT NULL DEFAULT 1,
    priority     INTEGER NOT NULL DEFAULT 0,    -- 数值越大优先级越高
    is_case_sensitive INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS ix_category_rules_enabled ON category_rules(is_enabled, priority DESC);

-- 标签体系
CREATE TABLE IF NOT EXISTS tags (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS media_tags (
    media_id INTEGER NOT NULL REFERENCES media_items(id) ON DELETE CASCADE,
    tag_id   INTEGER NOT NULL REFERENCES tags(id)        ON DELETE CASCADE,
    PRIMARY KEY (media_id, tag_id)
);
```

### 6.2 关键设计约束

| 约束 | 说明 |
|---|---|
| 时间统一 ISO8601 | SQLite 无原生 DateTime 类型；统一用 `DateTimeOffset.ToString("O")` 写入，读取时用 `DateTimeStyles.RoundtripKind` 解析，避免时区漂移 |
| `is_favorite` 不被覆盖 | Upsert 的 `ON CONFLICT DO UPDATE` 子句中**排除**该列，保住用户手动收藏 |
| 目录前缀查询转义 | `LIKE` 前缀匹配必须对 `%` `_` `\` 做 `ESCAPE '\'` 转义，否则用户目录下的通配符会导致误删 |
| 软删除 | 用户手动移除的条目写入 `deleted_utc`，扫描时跳过，避免「删除 → 重扫 → 又出现」 |
| 迁移机制 | 使用 `PRAGMA user_version` 记录版本号，每次启动按序执行未应用的迁移脚本，迁移在单个事务内完成 |

## 7. 功能模块实现方案

### 7.1 媒体库管理（需求 6）

**扫描流程**

```
选择文件夹 → 规范化路径 → 持久化到 library_folders
        ↓
MediaIndexingService.ScanAsync(folder, progress, ct)
        ↓
枚举文件（EnumerationOptions：递归 / 跳过隐藏·系统·临时·重解析点）
        ↓
按扩展名过滤（MediaFileClassifier）
        ↓
每 500 条批量 Upsert（单事务） → 上报进度
        ↓
对账：取该目录下既有路径 − 本次发现路径 → 批量软删除
        ↓
更新 folder.last_scan_utc
```

**关键实现要点**

1. **符号链接防护**：`AttributesToSkip` 必须包含 `FileAttributes.ReparsePoint`，防止目录环导致无限递归，同时避免越权读取链接指向的库外内容。
2. **去抖与节流**：`FileSystemWatcher` 事件先写入 `Channel<LibraryChange>`，后台泵按 1 秒静默期聚合成批，再统一上报，避免批量重命名/删除时触发数百次回扫。
3. **缓冲区溢出**：`InternalBufferSize` 设为 64 KB；`Error` 事件发生时记录日志并重建监视器。
4. **跨卷移动**：跨卷移动在 FSW 层面表现为「删除 + 新建」，按删除处理；同卷移动表现为 `Renamed`，按路径更新处理。
5. **增量策略**：文件已存在且 `modified_utc` 与 `file_size` 未变时跳过 Upsert，仅刷新 `indexed_utc` 的最近活跃时间。

**对外接口**

```csharp
Task<IndexingReport> ScanAsync(
    LibraryFolder folder,
    IProgress<IndexingProgress>? progress = default,
    CancellationToken cancellationToken = default);
```

### 7.2 图片浏览与编辑（需求 1）

**解码管线（三级回退）**

| 优先级 | 方案 | 说明 |
|---|---|---|
| 1 | WIC `BitmapDecoder` | 系统解码，支持 JPEG/PNG/GIF/WebP/TIFF/HEIC（含系统 HEIF 扩展）；对 JPEG 有硬件加速路径 |
| 2 | `ImageSharp` | WIC 不支持的格式（如 AVIF 未装扩展时）与编辑操作的统一处理入口 |
| 3 | 占位图 | 全部失败时展示「格式不支持」卡片，并提示安装对应扩展 |

**功能映射**

| 功能 | 实现方案 |
|---|---|
| 缩放 | `ScrollViewer` + `Viewbox`，支持 Ctrl+滚轮以光标为锚点缩放；`SemanticZoom` 仅在网格视图启用 |
| 旋转 | `BitmapTransform` / `BitmapEncoder` 无损旋转（JPEG 直写 Orientation 标记），EXIF Orientation 单独记录 |
| 全屏 | `AppWindow.SetPresenter(AppWindowPresenterKind.FullScreen)`，Esc 退出，隐藏标题栏与导航栏 |
| 幻灯片 | `DispatcherQueueTimer` 驱动，支持间隔配置、随机/顺序、淡入淡出过渡动画 |
| EXIF | `MetadataExtractor` 解析，右侧详情面板展示相机、镜头、光圈、快门、ISO、GPS（GPS 默认脱敏显示） |
| 裁剪 | 自绘 `CropOverlay` 控件（拖拽手柄 + 遮罩），支持自由/1:1/4:3/16:9/原始比例，输出走 `BitmapEncoder` |
| 基础编辑 | 亮度/对比度/饱和度通过 `ImageSharp` 的 `Mutate` 管线；**编辑非破坏性**——原图只读，结果另存副本并记录到编辑历史 |

### 7.4 正则分类管理（需求 4）

**规则模型**

```csharp
public sealed record CategoryRule(
    long Id, string Name, string Pattern, long CategoryId,
    MatchTarget Target, bool IsEnabled, int Priority, bool IsCaseSensitive);
```

`MatchTarget` 枚举：`FileName`（默认）`/ FullPath` / `Extension`。

**匹配流程**

```
加载已启用规则 → 按 Priority 降序、Id 升序排序（保证稳定）
        ↓
对每个待分类文件：依次尝试匹配，首个命中即停止（短路，避免全规则遍历）
        ↓
写入 media_items.category_id，同时记录命中规则 Id（用于「为什么归到这类」的溯源展示）
```

**安全：ReDoS 防护（强制）**

用户提供的正则表达式可能导致灾难性回溯，必须防护：

1. **编译超时**：`Regex` 构造时传入 `matchTimeout`（建议 1 秒），超时抛 `RegexMatchTimeoutException`，捕获后标记规则为「疑似危险」并禁用。
2. **批量匹配时限**：批量重算时为整批操作设置总时限，超时中断并回滚。
3. **输入长度截断**：仅对文件名（≤ 260 字符）或路径匹配，不把文件内容喂给正则。
4. **规则编辑即时校验**：用户在设置页保存规则时立即做一次试匹配，异常则拒绝保存并给出中文提示。

**批量重匹配**：后台任务分页（每页 1000 条）读取待分类条目，逐页重算并批量更新，支持取消与进度显示。

### 7.5 发现模式（需求 5）

- **随机算法**：SQL 层 `ORDER BY RANDOM() LIMIT n` 在大数据量下性能差，改为「先取 `COUNT(*)`，再在应用层生成随机偏移，按主键定位」的 O(1) 取样。
- **避免重复**：维护最近展示队列（默认 200 条），命中则重抽；队列满后 FIFO 淘汰。
- **加权（可选）**：支持按「收藏优先」「近期优先」「未分类优先」三种权重模式。
- **定时切换**：`DispatcherQueueTimer`，间隔 3s/5s/10s/30s/手动。
- **交互**：空格=下一张，F=收藏，X=跳过，Esc=退出；触屏支持左右滑动。

### 7.6 局域网 Web 访问（需求 3）

**路由表**

| 路由 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 响应式首页（内嵌静态资源，无外部依赖） |
| `/api/items` | GET | 分页列表，支持 `kind` / `category` / `date` / `q` 查询参数 |
| `/api/items/{id}` | GET | 条目详情（含 EXIF 摘要） |
| `/thumb/{id}` | GET | 缩略图（优先磁盘缓存，带 `ETag` 与长缓存头） |
| `/media/{id}` | GET | **原图/视频流，必须支持 `Range` 请求**（206 Partial Content） |
| `/api/login` | POST | 登录换取会话令牌 |
| `/api/health` | GET | 健康检查（不鉴权，仅返回版本） |

**关键实现要点**

1. **Range 请求**：解析 `Range: bytes=start-end`，返回 `206` + `Content-Range` + `Accept-Ranges: bytes`。视频拖动进度条强依赖此能力。
2. **鉴权**：首次启用时用户设置密码 → 使用 `Rfc2898DeriveBytes`（PBKDF2，10 万次迭代，随机 16 字节盐）存储哈希，**禁止明文或可逆加密**。登录成功后下发随机 256 位会话令牌（`RandomNumberGenerator.Fill`），令牌存内存并设过期时间（默认 8 小时）。
3. **只读模式**：默认开启，仅允许 GET；关闭写接口。
4. **网络绑定**：默认仅绑定局域网地址（自动枚举非回环 IPv4），提供开关；启动时输出可访问 URL 列表并在 UI 展示二维码。
5. **限流**：按来源 IP 做令牌桶限流（默认 60 req/min），超限返回 429；连续登录失败 5 次锁定该 IP 15 分钟。
6. **路径安全**：所有文件访问必须经 `PathGuard` 校验解析后的绝对路径位于已注册库目录内，**禁止**接受客户端传入的路径参数直接访问文件系统（`/media/{id}` 只接受数据库主键）。

## 8. 安全设计

对照安全基线逐条落实：

| 安全域 | 措施 |
|---|---|
| **SQL 注入** | 100% 参数化查询；动态条件使用 `(@p IS NULL OR col = @p)` 形式；禁止任何字符串拼接 SQL |
| **路径穿越** | 所有外部传入路径经 `PathGuard`：`Path.GetFullPath` 规范化 → 前缀比对（必须命中目录边界分隔符）→ 拒绝 `..`、驱动器号、UNC 未授权路径 |
| **认证与会话** | 密码 PBKDF2 加盐哈希存储；会话令牌 256 位 CSPRNG；默认 8 小时过期；支持一键吊销全部会话 |
| **Web 安全** | 响应头强制下发 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP（仅允许同源资源）；所有 HTML 输出经 HTML 编码 |
| **SSRF** | 本服务不发起任何对外请求，无 SSRF 面；若未来加入在线功能，需实现协议白名单 + IP 黑名单 + 禁用自动重定向 |
| **限流** | 按 IP 令牌桶（60 req/min）；登录失败 5 次锁 IP 15 分钟；单 IP 并发连接数上限 8 |
| **日志脱敏** | 禁止记录密码、会话令牌、完整路径中的用户名（对 `C:\Users\<name>\` 做掩码）；生产环境错误堆栈只写日志，前端只返回通用错误 |
| **ReDoS** | 见 §7.4，强制 `matchTimeout` + 批量时限 + 输入截断 |
| **文件上传** | Web 端默认只读，无上传面；若后续开放写入，需扩展名白名单 + 魔术字节校验 + 大小上限 + 服务端 UUID 重命名 |
| **密钥管理** | 禁止硬编码任何密钥；配置走 `%LOCALAPPDATA%` 下的用户配置文件，权限设为仅当前用户可读写 |
