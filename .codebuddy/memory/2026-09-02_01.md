## 第六轮：LayoutCycleException 嫌疑排除（00:24 会话实为启动噪声）＋ 三级输入探针

### 用户回传日志的重大反转
- `crash.log` 00:24:03 的记录是 `COMException ClassFactory (0x80040111)` + LimitedAccessFeatures
  —— **WASDK 每次启动都有的既有噪声**（00:11 同款），**不是** LayoutCycleException！
  00:24 会话布局循环从未发生。
- 时序：00:23:52 收藏夹加载完（58ms/0条）→ 00:24:03 用户点图库 →
  00:24:04.371 `LOAD|新建文件夹(2)|count=200` → STAT → **PROBE|0|1（回填生效、零预取）** →
  **THUMBWAIT/LOADTOTAL 永久缺失** → 卡点锁定在 `LoadThumbnailsForVisibleItemsAsync`
  （整页 200 张解码提交后 `Task.WhenAll` 未返回）。
- `PANEL` 在 00:24:07-20 持续正常输出（3~10 次/500ms、width 恒定 1007、children=200）
  → **UI 线程活着、布局正常、面板无辜**——「点击无效」但布局在跑。
- 撤层（IsQuerying=false）在代码顺序上位于 THUMBWAIT 之前，理论应已执行，但**无日志证明**。

### 本轮改动
1. **兜底撤层**（`ExecuteLoadAsync` finally）：sequence 匹配收尾时若 `IsQuerying` 仍为 true
   则强制撤除并记 `OVERLAY|force-hide`。覆盖层是不透明全内容区遮罩，任何提前退出路径
   （作废 return / 静默异常 / 取消传播）漏撤层都会永久吞掉全部点击——布局照常、日志照常、
   唯独点不动，与用户症状完全一致。正常路径幂等无害。
2. **三级输入探针**（全部【临时诊断】，结案后删）：
   - `NAVCLICK`（MainWindow.OnNavigationSelectionChanged）：点击是否到达 UI 事件层；
   - `OVERLAY|show=0/1`（SyncLoadingOverlay）：遮罩每次显隐留痕；
   - `THUMBSUBMIT|count`（LoadThumbnailsForVisibleItemsAsync 前）：整页解码提交留痕。
3. PANEL 日志保留。

### 复现时的判读表（下次用户回传 diag.log 按此二分）
| 现象 | 结论 |
|---|---|
| 无 NAVCLICK | 点击未到 UI 事件层 → 输入路由被吞（找全窗口透明遮挡 / NCP 配置） |
| 有 NAVCLICK 无 LOAD | 加载链路前段挂起（等帧/QueryAsync） |
| 有 LOAD 无 THUMBSUBMIT | 集合替换 EnqueueAsync 或统计阶段挂起 |
| 有 THUMBSUBMIT 无 THUMBWAIT | 整页解码 WhenAll 挂起（头号嫌疑：OneDrive 按需文件解码下载挂死） |
| OVERLAY show=1 后无 show=0 且无 force-hide | 遮罩卡死吞输入（兜底已加，理论上不应再现） |

### 方法论
- **crash.log 必须逐条看异常类型**，不能见 crash 就套用上次的结论：
  同一位置前后两条记录（00:13 LayoutCycle / 00:24 ClassFactory）性质完全不同。
- **「布局在跑 + 点击无效」≠ 死循环**：不透明遮罩卡住、命中测试失效、输入路由被吞
  都是这个表现。死循环判据（CPU 100% + 日志 0 增长）不满足时必须转向输入侧排查。
- **代码顺序 ≠ 执行顺序**：撤层写在 THUMBWAIT 之前不代表它执行了——异步链路上
  每个关键状态变化（尤其显隐）都应留痕，否则无从取证。
