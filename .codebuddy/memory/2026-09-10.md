## 关键事实（踩坑）
- `app.ico` 一度缺失导致 **CS7064**；`tools/gen-icon.ps1` 无法解析含渐变与内嵌位图的 `app-icon.svg`（它只支持纯色 path），改由 256 PNG 重新生成 ICO（临时脚本 `C:\Temp\gen-ico-from-png.ps1`）
- `using Windows.ApplicationModel.Activation` 会让 `LaunchActivatedEventArgs` 在 `Microsoft.UI.Xaml` 与 WinRT 之间二义（**CS0104**）→ 改用别名 `using IFileActivatedEventArgs = Windows.ApplicationModel.Activation.IFileActivatedEventArgs;`
- **CA1822** 在 `-warnaserror` 下是错误：`[RelayCommand]` 方法若不访问实例成员会被要求静态化
- 终端：嵌套 `powershell -Command "..."` 会吞噬内层 `$var`（诊断命令变量变空）；诊断脚本要写成 `.ps1` 再执行。含中文的 `.ps1` 必须 UTF-8 **with BOM**
- `Cert:` 驱动器不支持 `Remove-Item` 管道删除证书，改用 .NET `X509Store` 的 `Find` + `Remove`
- 自签证书导入 `Cert:\CurrentUser\Root` 用 `Import-Certificate` 会弹 UI（无人值守报"此操作中不允许使用 UI"），改用 .NET `X509Store` 直接写入

## 补充：注册已成功（同日后续）

最终包：`Pixbian_1.0.0.0_neutral__h94vh5tyrgn60`

真正的四个关键点：
1. **必须用两级证书**：单张自签证书同时充当根与叶子时链构建不稳定（signtool 报 `0x80096019`、Add-AppxPackage 报 `0x800B0109`）。改为根 CA（`CN=Pixbian Root`）签发代码签名叶子（`CN=Pixbian`）后 `signtool verify` 立即通过。
2. **根证书必须导入 LocalMachine**：包由 AppX 部署服务（系统上下文）校验，只看得见本机存储。仅导入 CurrentUser 会报 `0x800B010A`（无法建立到信任根颁发机构的证书链）。导入 `LocalMachine\Root` 需管理员。
3. **PFX 含两张证书时签名必须指定 `/sha1 <叶子指纹>`**，否则 SignTool 报"找到多个证书"而不签名。
4. **`Add-Type -AssemblyName System.Security` 会破坏 `CertificateRequest` 的类型解析**（构造函数的密钥参数被解析成 null）。因此脚本不用它，也因此不设置 EKU（`OidCollection` 在该程序集内）；未限定 EKU 的证书等同全用途，代码签名成立。

验证结果：

- `%LOCALAPPDATA%\Packages\Pixbian_*\LocalCache\Local\Pixbian` **不存在** → 未发生虚拟化，数据路径不变（`unvirtualizedResources` 生效）
- 应用从 `artifacts\win-x64\Pixbian.exe` 启动正常，无新增崩溃日志
