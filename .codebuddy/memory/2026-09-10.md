## 诊断：任务栏图标"背景不透明"
- 现象：生成的 app.ico 在任务栏显示背景不透明。
- 排查结论：文件透明机制正常，非 gen-icon.ps1 bug。
  - app-icon.svg 唯一绘制元素为内嵌 base64 PNG 的 `<image>`。
  - 内嵌位图主体为不透明深灰 #393A3A（占宽约 84%），即"带底色的成品图标图"，四角/边缘透明；中心前景。
  - 生成的 app.ico（16/32/48/256）四角 alpha 均为 0，透明通道保留正常。
  - 仓库无 .appxmanifest → unpackaged 应用，任务栏图标取自嵌入 EXE 的 app.ico。
- 根因：用户看到的"不透明背景"= 图标自带的深灰底色方块，被如实渲染进 ICO。非文件/脚本缺陷。

## 修复：替换 SVG 内嵌位图为透明背景版
- 用户提供透明素材：Square44x44Logo.targetsize-256_altform-unplated.png（256×256，四角 A=0，unplated=无底板）。

  3. `git checkout HEAD -- app-icon.svg` 恢复被前次正则 bug 损坏的文件（丢弃用户工作区未提交修改；副作用需提示用户）。

- 验证：WPF IconBitmapDecoder 采样各尺寸四角 A=0、中心 A=255 前景正常、BPP=32。
- 涉及文件：src/Pixbian/Assets/app-icon.svg、src/Pixbian/Assets/app.ico。

- 教训：①data URI MIME 不一定是标准 `image/png`，HEAD 用的是非标准 `data:img/png`，正则必须宽容（`data:[^"]+` 或匹配 base64 字符集 `[A-Za-z0-9+/=]+`，不要假设 `image/` 前缀）；②String.Replace("",x) 抛 ArgumentException 且会使后续变量未赋值，传空前先校验长度；③Git checkout -- file 会丢弃用户工作区修改，修复损坏文件时必须告知副作用。

## 实施：.NET 10 迁移试点（分支 feature/net10-migration，同日第九批）

**改动**：安装 .NET 10 SDK 10.0.401（winget）；`global.json` 8.0.424→10.0.401；`Directory.Build.props` LangVersion 12→13 + CA1873 豁免；9 个 csproj TFM net8.0→net10.0；CI 切 10.0.x；依赖包版本全部未动（M.E.* 8.x 与 Sqlite 8.0.11 在 net10 兼容）。

**核心发现（重要沉淀）：XAML 编译器 CWD 断裂**——net10 SDK 的 MSBuild 下，`Exec` 启动 `XamlCompiler.exe` 的工作目录=构建启动目录（net8 下行为不同），而 XAML 页面以项目相对路径传入编译器按 CWD 解析 → 从仓库根构建 sln 时全部页面解析失败，表现为 `WMC0001 Unknown type` 连锁 + `WMC9999` 内部 NRE，极易误判为「WASDK 不支持 net10」。**排查法**：手动重放 `XamlCompiler.exe input.json output.json`（ExitCode 1 且 stderr 为空——Exec 的 IgnoreExitCode=true 吞掉退出码；真实错误在 output.json 的 `MSBuildLogEntries` 字段；`WMC9999` 是 OutputDeserializer 对坏 output 的 NRE 假象）→ 以项目目录为 CWD 重放即 ExitCode 0 → 锁定 CWD。**修复**：`XamlCompilerExePath` 指向构建期 `WriteLinesToFile` 生成的包装脚本（`cd /d 项目目录 && 真实编译器 %*`），与启动目录解耦；%22 转义引号、%25 转义 %。

**net10 分析器新规则**：CA1859（私有字段/参数 IReadOnlyList→List 具体化，仅当全部赋值/调用点都是 List 时才报）5 处照改；CA1873（LoggerMessage 调用点参数为方法调用时建议 IsEnabled 守卫）3 处精准豁免（AppLog 恒启用、参数为轻量脱敏函数，守卫零收益）——Directory.Build.props NoWarn 有 NU1900 先例。

**验证**：从仓库根构建 sln 0 警告 0 错误；测试 303 全过（Core 230 / Web 59 / Imaging 14）。
**手工验证**：✅ 用户确认全链路无误（应用启动与回归通过）——net10 试点完成，具备合入 main 条件。
**遗留**：双 TFM 矩阵（合入 main 前评估）；MVVMTK0045 豁免随 [ObservableProperty]→partial property 迁移移除。
