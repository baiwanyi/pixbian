## 冻结形态取证（关键转折）
- `dotnet-stack report`（已装 dotnet-stack 9.0.661903）：**全进程仅 3 托管线程全空闲，
  UI 线程停在 Application.Start 消息循环、无业务帧**，Responding=True、CPU 3 秒增量≈0

## 根因（定案）
`GalleryViewModel.WaitForNextRenderFrameAsync` 订阅 `CompositionTarget.Rendering` 等待渲染帧，
**该订阅与渲染 tick 抢占执行窗，令合成呈现停摆**（UI 活、布局 pass 死、画面冻在最后一帧）。
与 `ThumbnailPresenter` 同类机制早前的禁用注释（"UI 线程存活、布局照常、画面冻结在最后一帧"）
互相印证。**分水岭修正：不是 e75be83，是 84c9e74 引入此机制**（概率性，当时"连启 4 次稳定"
是小样本误判）。

# 后续两轮：缩略图静默全灭（0x8001010E）+ 快速切换未响应，均已修复（用户确认正常）

## 缩略图全灭 → HRESULT 定案 RPC_E_WRONG_THREAD
- 症状：不冻了但骨架屏常驻；THUMBWAIT 正常完成而 THUMB 0 条产出——失败全静默黑盒
- 取证迭代：catch 全量记录异常类型 → COMException（Message 空）→ 加 HResult →
  **`0x8001010E`（RPC_E_WRONG_THREAD）**
- 根因：**第 20 轮 ConfigureAwait(false) 修复的回归**——编码段落线程池后
  `SynchronizationContext.Current` 变 null，`CreateBitmapAsync` 的 ConfigureAwait(true)
  切不回 UI 线程 → `new BitmapImage`/`SetSourceAsync` 在线程池 → 线程亲和异常。
  **ConfigureAwait(true) 语义是"恢复到各 await 点当时捕获的上下文"，中途 false 后末端 true 回不去**
- 修复：`ThumbnailService` 注入 `DispatcherQueue`（单例 UI 线程构造，回落 GetForCurrentThread），
  位图创建经 `TryEnqueue` + `TaskCompletionSource`（RunContinuationsAsynchronously 防内联）
  显式切回 UI 线程，async void 桥接 + 异常收口到任务源
- 同时：单条编码 20s 超时（`WaitAsync`，挂死 IO 不再占死信号量槽位）、catch 扩展
  TimeoutException/COMException、`WhenAll` 90s 兜底（状态机收口，解码后台继续）

## 快速切换未响应（UI 线程 2~5 秒/次钉死）
- TICK 间隙扫描：切换期间 2.8s/2.5s/4.7s 间隙，而管线日志全部正常完成
  → UI 线程被「200 容器销毁+创建+全量重排+取消扫描」钉死，快速切换 ×10 = 未响应
- 修复三件套：① 替换块内补代数检查（过期请求跳过整块 UI 重建，快速切换只执行最后一次）
  ② `PrefetchDimensionsAsync` 加 sequence 参数，写回块内复核 ③ `GalleryPage` ViewChanged
  偏移去重（集合替换误触发的 O(n) 容器扫描跳过）
- 踩坑：CA1068（CancellationToken 须末参）、CA1822（实验版方法改 static）、CA2016
  （WaitAsync 须转发 token）——`-warnaserror` 下全为错误

## 经验补充
- **ConfigureAwait(true) 不是"回到 UI 线程"**：中途任一 await 用 false 脱离上下文后，
  后续 true 无法切回；跨线程回归 UI 的唯一可靠手段是显式 DispatcherQueue 调度
- **服务层需要 UI 亲和时，经构造注入 DispatcherQueue + TCS 桥接**是可靠模式
- **"正常完成"≠"有效工作"**：THUMBWAIT 完成但 0 产出 = 全员静默失败，必须给 catch 加取证日志
  （异常类型 + HResult）；WinRT 的 COMException 常无 Message，HResult 是唯一线索
